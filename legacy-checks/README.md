# 미리 만든 안전망 (레거시 검사 도구)

이 폴더에는 레거시 10개마다 미리 만들어 둔 안전망이 있어요. 안전망은 코드를 고친 뒤에도 프로그램이 예전과 똑같이 동작하는지 확인하는 장치예요. 막혔을 때 꺼내 쓰는 예비 도구예요.

## 들어 있는 것

폴더 이름은 `labs/legacy/`의 레거시 폴더 이름과 같아요. 폴더마다 두 가지가 들어 있어요.

| 경로 | 내용 |
| --- | --- |
| `<폴더 이름>/expected/` | 원본 프로그램을 여러 입력으로 실제로 실행해서 남긴 기록이에요. 화면 출력, 만든 파일, 종료 코드가 들어 있어요. 어떤 입력으로 돌렸는지는 `cases.json`에 적혀 있어요. |
| `<폴더 이름>/verify.py` | 내가 고친 프로그램을 같은 입력으로 실행하고, 결과를 `expected/`의 기록과 비교하는 스크립트예요. |

종료 코드는 프로그램이 끝날 때 남기는 숫자예요. 0이면 정상으로 끝났다는 뜻이에요. 레거시를 부르는 다른 프로그램이 이 숫자를 보고 다음 일을 정해서, 이 숫자도 예전과 같아야 해요.

| 폴더 | 기록한 사례 | 비교하는 것 | 원본을 그대로 돌릴 때 필요한 것 |
| --- | --- | --- | --- |
| `settle-cs` | 7개 | 화면 출력, 종료 코드 | .NET 8 SDK |
| `claim-cs` | 6개 | 화면 출력, 종료 코드 | .NET 8 SDK |
| `room-java` | 6개 | 화면 출력, 종료 코드 | JDK 17 이상 |
| `points-java` | 7개 | 화면 출력, 알림 파일, 종료 코드 | JDK 17 이상 |
| `payroll-java` | 8개 | 화면 출력, 종료 코드 | JDK 17 이상 |
| `inventory-py` | 6개 | 화면 출력, 발주 파일, 종료 코드 | Python 3.9 이상 |
| `expense-py` | 6개 | 화면 출력, 결과 파일(정산 CSV, 메일, 감사 로그), 종료 코드 | Python 3.9 이상 |
| `notice-js` | 6개 | 만든 파일(`outbox.json`, `summary.txt`), 종료 코드 | Node.js 18 이상 |
| `triage-js` | 8개 | 화면 출력, 종료 코드 | Node.js 18 이상 |
| `library-php` | 8개 | 화면 출력, 저장소 파일, 종료 코드 | PHP 8 이상 |

모든 폴더에서 `data/`의 입력 파일이 실행 중에 바뀌었는지도 함께 봐요.

## 6교시 예시 문장과 결과 견본

`examples/` 폴더에 6교시 실습에서 보내는 예시 문장([examples/prompts.md](examples/prompts.md))과, 그 문장을 실제로 보냈을 때 나온 결과 견본([examples/results/](examples/results/))이 있어요. 안전망 만들기, 첫 단계 계획, 한 단계 고치기, 문서 쓰기의 실제 답을 볼 수 있어요. 이 폴더는 내 레거시 폴더로 복사하지 않아요.

## 왜 레거시 폴더 안에 없나요

레거시 폴더에는 누리상사에서 넘겨받은 것만 들어 있어요. 이 안전망은 누리상사가 만든 것이 아니에요. 수업용으로 따로 만든 도구예요.

6교시에는 이런 안전망을 Claude와 함께 직접 만들어요. Claude에게 "고치기 전에 지금 동작을 기록해 두자"고 하면, 원본을 여러 입력으로 돌려서 결과를 저장하고 비교 스크립트를 만들어 줘요. `/init`을 해 보면 Claude가 이 방법을 먼저 제안하기도 해요. 이 폴더는 그 과정이 막혔을 때 쓰는 예비 도구예요. 예를 들어 원본을 돌릴 실행 환경이 내 PC에 없거나, 시간이 모자랄 때 꺼내 써요. 내가 만든 안전망과 이 안전망을 둘 다 돌려서 결과를 맞춰 봐도 좋아요.

## 왜 Java나 C# 레거시인데 Python인가요

`verify.py`는 프로그램의 코드를 읽지 않아요. 프로그램을 실행하고, 나온 결과를 기록과 비교하기만 해요. 그래서 레거시가 어떤 언어로 되어 있어도 상관없어요. 원본을 Java에서 Python으로 옮기거나 C#을 Java로 옮겨도, 같은 `verify.py`로 검사할 수 있어요.

Python은 Python 3.9 이상이면 되고, 표준 라이브러리만 써요. 따로 설치할 패키지가 없어요.

## 쓰는 법

### 1. 내 레거시 폴더에 복사해요

수업에서 쓰는 내 레거시 폴더(`~/legacy/<폴더 이름>`)에 `verify.py`와 `expected/`를 둘 다 복사해요. 아래는 `room-java`의 예예요. 강의 자료를 `~/dbinc-ai-course`에 받았다고 가정했어요.

macOS와 Linux에서는 이렇게 해요.

```bash
cp -R ~/dbinc-ai-course/labs/legacy-checks/room-java/. ~/legacy/room-java/
```

Windows PowerShell에서는 이렇게 해요.

```powershell
Copy-Item -Recurse "$HOME\dbinc-ai-course\labs\legacy-checks\room-java\*" "$HOME\legacy\room-java\"
```

탐색기에서 `verify.py` 파일과 `expected` 폴더를 끌어다 놓아도 돼요. 둘 다 복사하면 `verify.py`, `expected/`, `src/`, `data/`가 한 폴더에 나란히 있게 돼요. `verify.py`는 자기가 있는 폴더를 기준으로 프로그램을 실행해서, 이렇게 놓아야 동작해요.

### 2. 원본으로 먼저 돌려 봐요

내 레거시 폴더 안에서 실행해요.

```bash
cd ~/legacy/room-java
python3 verify.py
```

옵션 없이 실행하면 폴더 안의 원본 프로그램을 실행해서 비교해요. 받은 그대로라면 모든 사례가 `OK`이고, 마지막 줄이 `통과 6/6`처럼 나와요. Windows에서는 `python3` 대신 `python`이나 `py`를 써요.

원본을 돌리려면 위 표의 실행 환경이 내 PC에 있어야 해요. 없으면 `verify.py`가 무엇이 없는지 알려 주고 멈춰요. 그래도 원본의 결과는 `expected/`에 이미 기록되어 있어요. 그래서 옮긴 프로그램은 다음 단계처럼 `--cmd`로 검사할 수 있어요.

### 3. 고친 프로그램이나 옮긴 프로그램을 검사해요

`--cmd`에 내 프로그램을 실행하는 명령을 적어요. `verify.py`가 사례마다 정해진 인자를 명령 뒤에 붙여서 실행해요. 명령은 이 폴더에서 실행되니, 명령 안의 경로도 이 폴더를 기준으로 적어요.

```bash
python3 verify.py --cmd "python3 port/main.py"
python3 verify.py --cmd "node port/main.js"
python3 verify.py --cmd "java -cp out com.nuri.room.RoomBatch"
```

언어에 따라 쓸 수 있는 옵션이 더 있어요.

| 옵션 | 쓸 수 있는 폴더 | 하는 일 |
| --- | --- | --- |
| `--java <폴더>` | `room-java`, `points-java`, `payroll-java`, `settle-cs`, `claim-cs` | 그 폴더의 `.java` 파일을 모두 컴파일하고 실행해서 비교해요. C#을 Java로 옮겼을 때도 써요. |
| `--main <클래스>` | `--java`를 쓰는 폴더 | `main`이 있는 클래스가 여러 개일 때 하나를 골라요. |
| `--src <폴더>` | `library-php` | 그 폴더의 `batch.php`와 `overdue_report.php`를 실행해서 비교해요. |
| `--keep` | `notice-js` | 출력 폴더(`.verify-out/`)를 지우지 않고 남겨요. |

모든 폴더에서 쓸 수 있는 옵션도 있어요.

| 옵션 | 하는 일 |
| --- | --- |
| `--case <사례 이름>` | 사례 하나만 검사해요. 여러 번 줄 수 있어요. |
| `--list` | 사례 목록과 인자를 보여 줘요. |
| `--help` | 그 폴더의 옵션을 모두 보여 줘요. |

### 4. 결과를 읽어요

- 사례마다 `OK`나 `FAIL`이 나와요. `FAIL`이면 처음으로 달라진 줄을 기록과 내 결과로 나란히 보여 줘요.
- 마지막 줄은 `통과 N/N`이에요.
- 줄바꿈 방식(Windows의 CRLF와 macOS의 LF) 차이는 같은 것으로 봐요.
- 표준 오류(stderr)에 찍힌 글은 비교하지 않아요.
- 실행하면서 생기는 출력 폴더(`actual/`, `verify-out/`, `.verify-out/`)는 레거시 폴더의 `.gitignore`에 이미 들어 있어서 커밋에 섞이지 않아요.
- `verify.py`와 `expected/`는 커밋해도 되고 하지 않아도 돼요. 팀과 함께 쓸 안전망이면 커밋해 두는 편이 좋아요.

## 종료 코드

`verify.py`도 끝날 때 종료 코드를 남겨요. 자동으로 검사를 돌리는 스크립트에서 이 숫자를 써요.

| 코드 | 뜻 |
| --- | --- |
| 0 | 모든 사례가 기록과 같아요. |
| 1 | 다른 사례가 하나 이상 있어요. `data/`의 입력 파일이 바뀌었을 때도 1이에요. `room-java`, `points-java`, `payroll-java`에서 `--java`로 준 코드가 컴파일되지 않을 때도 1이에요. |
| 2 | 검사를 시작하지 못했어요. 없는 사례 이름, 없는 폴더, 잘못 쓴 옵션, 실행 환경이 없는 경우예요. `settle-cs`와 `claim-cs`에서 `--java`로 준 코드가 컴파일되지 않을 때도 2예요. |
| 3 | `payroll-java`와 `library-php`에서만 나와요. JDK나 PHP를 찾지 못했거나, 찾았지만 실행되지 않을 때예요. 다른 폴더에서는 이 경우 2가 나와요. |

## 강사용 메모

- `expected/`는 원본을 실제로 실행해서 기록했어요. 손으로 고치지 않아요.
- 원본이나 `data/`를 바꿨을 때만 다시 기록해요. 도구는 `labs/legacy/_reference/<폴더 이름>/tools/record_expected.py`에 있어요. 원본은 `labs/legacy/<폴더 이름>`에서 실행하고, 결과는 이 폴더의 `expected/`에 써요.
- 강사용 답을 검사하는 방법은 `labs/legacy/_reference/<폴더 이름>/README.md`에 있어요. 리포 안의 레거시 폴더를 더럽히지 않도록, 레거시 폴더를 임시 폴더에 복사하고 이 검사 도구를 넣어서 검사해요.
