# 6교시 예시 문장 모음

6교시(레거시 리팩토링과 문서) 실습에서 Claude에게 보내는 문장을 모았어요. 발표의 "예시" 칸과 같은 문장이에요. 그대로 써도 되고, 내 말로 바꿔도 돼요. **굵게 쓴 곳**이 내 레거시에 맞게 바꿀 곳이에요.

문장 옆에 "실제로 보냄"이라고 적은 것은 강사가 레거시를 복사한 폴더에서 Claude Code로 실제로 보내 본 문장이에요. 그때 나온 답은 [results/](results/) 폴더에 견본으로 있어요. "돌려 보지 않음"이라고 적은 것은 같은 틀로 만든 문장이에요.

모든 실습은 5교시에 쓴 내 레거시 폴더(`~/legacy/<내 레거시>`)를 Code 탭에서 열고 해요.

## 1. 내 레거시에서 나쁜 곳 찾기 (2부 끝, 3분)

- 모드: **Manual**로 둬요. 앱은 폴더마다 마지막 모드를 기억해서 5교시 끝의 Accept edits로 열릴 수 있으니 입력창 아래에서 바꿔요. 파일을 읽기만 하는 질문이라 대개 승인 카드가 뜨지 않아요. 명령 승인 카드가 뜨면 파일을 고치는 명령이 아닌지 보고 허락해요.
- 세션: **+ New session**으로 새 세션을 열어요.

> 이 저장소에서 **한 함수가 읽기부터 쓰기까지 다 하는 곳**을 찾아 줘. 파일 이름과 줄 번호로 보여 주고, 그 코드가 하는 일을 순서대로 쉽게 설명해 줘. 아직 고치지 마.

실제로 보냄: expense-py, 24초. 답은 [results/1-find-expense-py.md](results/1-find-expense-py.md)예요.

굵게 쓴 곳은 내 레거시 칸에 맞게 바꿔요.

| 칸 | 레거시 | 굵게 쓴 곳에 넣을 말 | |
| --- | --- | --- | --- |
| ① 맥에서 못 띄우는 .NET | `settle-cs`, `claim-cs` | Java로 옮기면 결과가 달라질 줄 | 돌려 보지 않음 |
| ② if-else 덩어리 | `room-java`, `inventory-py`, `library-php` | 같은 검사가 여러 벌 복사된 곳 | 실제로 보냄: inventory-py 27초, [답](results/1-find-inventory-py.md) |
| ③ 한 함수에 다 넣기 | `points-java`, `expense-py`, `triage-js` | 한 함수가 읽기부터 쓰기까지 다 하는 곳 | 실제로 보냄: expense-py 24초, [답](results/1-find-expense-py.md) |
| ④ 사람마다 다른 스타일 | `payroll-java`, `notice-js` | 같은 규칙을 사람마다 다르게 쓴 곳 | 실제로 보냄: payroll-java 1분 26초, [답](results/1-find-payroll-java.md) |

- 답에 여러 곳이 나오면 그중 하나만 골라 파일에서 그 줄을 열어 봐요. payroll-java에서는 일곱 곳이 나왔어요.
- Claude가 원본을 돌려 보려고 명령 승인 카드를 띄우기도 해요(payroll-java). 파일을 고치는 명령이 아니면 허락해도 되고, 3분 안에 끝내려면 거절해도 돼요.

내 칸을 모르겠으면 네 가지를 다 적어서 물어요(돌려 보지 않음).

> 이 저장소에 오늘 본 나쁜 코드 네 가지(.NET이라 맥에서 못 띄움, 같은 검사가 여러 벌 복사됨, 한 함수에 다 넣음, 사람마다 다른 스타일) 가운데 무엇이 있는지 찾아 줘. 가장 심한 곳 하나를 파일 이름과 줄 번호로 보여 주고, 그 코드가 하는 일을 쉽게 설명해 줘. 아직 고치지 마.

## 2. 안전망 만들기 (3부, 4분)

- 모드: **Accept edits**. 파일을 만들어야 해서예요. 원본을 실행하는 명령은 승인 카드가 뜨니 허락해요.
- 세션: 새 세션.

> 리팩토링하기 전에 지금 동작을 기록해 두고 싶어. **data/**의 입력들로 원본을 실행해서 결과를 저장하고, 나중에 고친 코드의 결과와 같은지 비교하는 방법을 만들어 줘. 원본 코드는 고치지 마.

실제로 보냄: room-java 1분 41초, expense-py 1분 4초. expense-py에서 나온 답은 [results/2-safety-net-expense-py.md](results/2-safety-net-expense-py.md)예요.

- 바꿀 곳: 입력 폴더 이름. 레거시 열 개 모두 입력이 `data/`에 있어서 대부분 그대로 써도 돼요.
- Claude가 "모두 같다"고 하면 이어서 "커밋해 줘"라고 보내요.
- 막히면: 원본을 돌릴 실행 환경(JDK, Node, PHP, .NET)이 없으면 `labs/legacy-checks/<내 레거시>/`의 `expected/`와 `verify.py`를 내 레거시 폴더로 복사하고, "python3 verify.py를 돌려 줘"라고 보내요. 쓰는 법은 [../README.md](../README.md)에 있어요.
- 더 해 보기(돌려 보지 않음): "복사본에서 한 줄을 망가뜨려 비교가 다름을 잡는지 보여 줘. 원본은 고치지 마."

## 3. 실습 1판: 내 레거시, 추천 메뉴 (10분)

- 세션: 안전망을 만든 그 세션에서 이어서 해요.
- 첫 문장은 **Plan** 모드로 보내요.
- 계획이 오면 지킬 것, 안 할 것, 확인 방법이 있는지 읽어요. 승인 카드에서 승인하면 Claude가 계획을 끝까지 바로 고쳐요. 오늘은 한 걸음씩 보려고 승인 대신 **No, keep planning**을 고르고, 모드를 **Accept edits**로 바꾼 뒤 둘째 문장을 보내요. 아래 실제 기록도 이렇게 계획과 고치기를 나눠 보냈어요. 승인 카드 글자는 터미널판 문구라서 앱에서는 다를 수 있어요.

틀은 이래요.

> **(방향)** 조금씩 바꾸고 싶어. 먼저 **(첫 단계에서 할 일)** 첫 단계를 계획해 줘. 동작은 그대로여야 하고, 안전망으로 확인해.

실제로 보낸 두 문장이에요.

> **한 함수가 다 하는 코드를 가운데(계산 규칙)와 바깥(파일, 메일, 화면)으로** 조금씩 나누고 싶어. 먼저 **메일을 만드는 부분을 바깥으로 떼어 내는** 첫 단계를 계획해 줘. 동작은 그대로여야 하고, 안전망으로 확인해.

실제로 보냄: expense-py, 46초. 계획은 [results/3-plan-expense-py.md](results/3-plan-expense-py.md)예요.

> **절차지향 코드를 객체지향으로** 조금씩 바꾸고 싶어. 먼저 **예약할 때와 바꿀 때 두 군데에 복사된 겹침 검사를 한 곳으로 모으는** 첫 단계를 계획해 줘. 동작은 그대로여야 하고, 안전망으로 확인해.

실제로 보냄: room-java, 1분 9초. 발표 4부에서 보여 주는 계획이에요.

계획을 읽은 뒤 승인 대신 No, keep planning을 고르고, 모드를 Accept edits로 바꿔 보내요.

> 좋아, 첫 단계만 해 줘. 끝나면 안전망으로 비교해 줘.

실제로 보냄: expense-py, 35초. 결과는 [results/4-step-expense-py.md](results/4-step-expense-py.md)와 바뀐 줄 [results/4-step-expense-py.diff](results/4-step-expense-py.diff)예요. 비교가 모두 같으면 "커밋해 줘"라고 보내요.

## 4. 실습 2판: 다른 레거시, 다른 메뉴 (11분)

준비 순서예요.

1. 강의 자료의 `labs/legacy/`에서 1판과 다른 레거시 폴더 하나를 `~/legacy/`로 복사해요.
2. 그 폴더를 Code 탭에서 열고 새 세션에서 "git 저장소로 만들고 받은 그대로 커밋해 줘"라고 보내요.
3. `labs/legacy-checks/`에서 같은 이름 폴더의 `expected/`와 `verify.py`를 새 폴더로 복사해요. 새 폴더에는 안전망이 없어서 이것을 안전망으로 써요.

화면이 있는 레거시(`triage-js`, `library-php`)에서는 Plan 모드로 이렇게 보내요.

> 화면과 **밤 배치**가 같은 **분류** 규칙을 따로 갖고 있어서 서로 달라졌어. 규칙을 한 곳으로 모으는 첫 단계를 계획해 줘. 배치 결과는 그대로여야 하고, python3 verify.py로 확인해. 아직 고치지 마.

실제로 보냄: triage-js, 57초. 계획은 [results/5-plan-triage-js.md](results/5-plan-triage-js.md)예요. `library-php`는 굵게 쓴 곳을 "일괄 처리", "대출"로 바꿔요(PHP가 없어서 돌려 보지 않음).

다른 메뉴로 하고 싶으면 위 "레거시마다 첫 문장" 표에서 골라요. 그 문장 끝에 "python3 verify.py로 확인해"를 붙여요.

시간이 되면 1판처럼 No, keep planning을 고르고, 모드를 Accept edits로 바꿔 보내요(돌려 보지 않음).

> 좋아, 첫 단계만 해 줘. 끝나면 python3 verify.py로 확인해 줘.

- C#을 Java로 옮겼으면 "python3 verify.py --java port로 확인해 줘"처럼 옮긴 폴더 이름을 알려 줘요.
- 화면은 verify.py가 검사하지 않아요. 화면을 바꿨으면 브라우저로 직접 열어 봐요(`triage-js`는 `web/index.html`).
- 시간이 모자라면 계획을 받아 읽는 데까지만 해도 돼요.
- `library-php`는 PHP가 있는 PC에서만 verify.py가 돌아가요. PHP가 없으면 "php를 찾지 못했어요"와 `통과 0/8`이 나와요. 그때는 `triage-js`로 바꿔요.
