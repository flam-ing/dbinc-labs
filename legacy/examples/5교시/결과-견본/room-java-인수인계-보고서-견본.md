# RoomBatch 인수인계 보고서

총무팀 회의실 예약 배치(RoomBatch)를 넘겨받는 분이 첫날 읽을 문서예요. 근거는 `파일:줄`로 달았어요. 실행 결과는 2026-10-17에 저장소의 `data/` 파일을 실제로 돌려서 확인한 값이에요(로컬 OpenJDK 21, `-encoding UTF-8` 빌드).

목차

1. 시스템 한 장 요약
2. 위험한 곳
3. 코드와 문서가 어긋난 곳
4. 위키·이슈에만 있는 이유
5. 6교시에 고칠 후보

---

## 1. 시스템 한 장 요약

### 하루 흐름

```
사원 → 봇 → D:\room\req\yyyyMM.txt 에 한 줄씩 추가
        ↓ (매일 23:00, Windows 작업 스케줄러)
RoomBatch 가 그달 파일 전체를 처음부터 다시 처리
        ↓ stdout
총무팀 공유 폴더 room_yyyyMMdd.txt → 아침에 공지
```

- 근거: `wiki/batch-ops-memo.md` 1절.
- 예약을 따로 저장하지 않아요. 매일 밤 파일 전체를 다시 처리해서 예약표를 새로 만들어요.
- 그래서 예약번호(`R0001`…)는 **성공한 RSV 순서대로 매일 다시 매겨져요**. 이게 이 시스템에서 가장 중요한 제약이에요(2절 1번).
- 원래는 그룹웨어 DB에 저장했어요. 2010-07 보안 점검 때 DB 계정이 막혀서 "임시로" 파일 방식으로 바꿨고, 지금도 그대로예요(`RsvManager.java:15`, ops memo 2절). DB 코드는 주석으로 남아 있어요.

### 코드 구조 (`src/com/nuri/room/`, 약 680줄)

| 클래스 | 하는 일 |
| --- | --- |
| `RoomBatch` | `main`. 첫 줄에서 시간대를 `Asia/Seoul`로 고정해요(:22). 파일을 UTF-8로 읽고, 빈 줄과 `#` 줄은 건너뛰어요. 나머지 줄은 `RsvManager.process`에 넘기고, 끝에 예약표와 건수를 찍어요. 종료 코드는 인자 없음 1, 파일 열기 실패 2예요. |
| `RsvManager` | `process`가 `split(",")`로 나눈 뒤 RSV/CXL/CHG/QRY로 분기해요. 명령은 대소문자를 가리지 않아요. 상태는 모두 `public static` 전역이에요(:19-26). |
| `RsvPrinter` | 상태가 `A`인 예약만 골라요. `날짜+회의실+시작` **문자열**을 키로 버블 정렬해서 찍어요. |
| `RsvUtil` | 날짜·시각 변환과 포맷을 맡아요. `chkRoom`은 회의실 이름을 번호로 바꾸면서 **입력 배열을 직접 고쳐요**(:25). |
| `RoomInfo` | 회의실 목록이 소스에 하드코딩돼 있어요. R06은 주석 처리됐어요(2010-06 폐지). |
| `Const` | 예전 규칙 값이 들어 있지만 **아무 데서도 쓰지 않아요**. |

## 2. 위험한 곳 (심각한 순서)

### 1. 예약번호가 매일 다시 매겨져요
- 번호는 `iSeq++`에서 나와요(`RsvManager.java:146`). 성공한 RSV일 때만 올라가요.
- 그래서 앞쪽 RSV 하나라도 성공/실패가 뒤집히면 그 뒤 번호가 모두 밀려요. 그러면 파일에 이미 쌓인 CXL/CHG가 **다른 사람의 예약**을 취소하거나 바꿔요.
- 규칙을 바꾸는 수정은 모두 이 영향을 따져야 해요. ROOM-23을 미뤄 둔 이유이기도 해요.

### 2. 한 줄 때문에 그날 배치 전체가 멈출 수 있어요 (이번에 찾은 것, 재현함)
- 쉼표만 있는 줄(`,`)을 `split(",")`하면 길이 0인 배열이 나와요.
- 그런데 `arr[0]`을 `try` 밖(`RsvManager.java:45-46`)에서 읽어요. `main`은 `IOException`만 잡아요.
- 결과: `ArrayIndexOutOfBoundsException`이 나고, 그 뒤 줄과 **예약표가 전혀 찍히지 않아요**.
- 종료 코드는 1이에요. "인자 없음"과 같은 값이라 스케줄러 쪽에서 원인을 구분하기 어려워요.
- 재현 방법: 아무 정상 줄 다음에 `,` 한 줄을 넣어 돌려 보세요.
- 공백만 있는 줄은 `trim()` 덕분에 빈 줄로 걸러져서 괜찮아요. 문제는 쉼표만 있는 줄이에요.

### 3. `TimeZone.setDefault(Asia/Seoul)` (`RoomBatch.java:22`)
- 절대 지우면 안 돼요.
- 2011-03에 새 서버가 미국 서부 시간대였어요. 미국 서머타임이 시작되자 `dayDiff`가 하루 적게 나왔고, 15일 뒤 예약이 2주 검사를 통과했어요(ops memo 4절).
- 인프라팀은 서버 시간대를 바꾸지 않겠다고 했어요. 그래서 이 줄이 유일한 방어선이에요.

### 4. 500건 한도
- 예약은 `arrRsv[500][10]`(:19)에 담아요. 취소된 칸은 다시 쓰지 않아요.
- 501번째로 성공하는 RSV는 예외가 나서 "형식 오류"로 떨어져요. 그 전에 `iSeq++`가 먼저 돌아서 번호도 하나 빠져요.
- 2010-12에 실제로 터졌어요. 그 뒤로 봇이 매달 새 파일을 쓰도록 바꿔서 피하고 있어요. 한 달 RSV가 500건을 넘으면 다시 터져요.

### 5. 시각을 문자열로 비교해요 (ROOM-23)
- `날짜+시각`을 이어 붙인 문자열로 비교해요. 이 방식이 쓰이는 곳은 겹침(:135-139, :271-275), 지난 시간(:112, :257), 청소(:127), 정렬(`RsvPrinter`)이에요.
- 옛 봇이 보내는 세 자리 시각(`930`)이 들어오면 이렇게 돼요.
  - 겹침 검사를 빠져나가요.
  - `93:0`으로 찍혀요.
  - `1000`보다 뒤로 정렬돼요.
  - **R01 청소 검사도 빠져나가요**. `"900".compareTo("1300") > 0`이기 때문이에요. 이 부분은 이슈에 적혀 있지 않아요.
- 옛 봇은 2013년에도 총무팀 PC에 남아 있었어요(ROOM-23 마지막 댓글).

### 6. 예외를 삼켜서 원인이 안 보여요
- `process`는 모든 예외를 "형식 오류" 하나로 바꿔요(:59-61). 스택 트레이스는 주석 처리돼 있어요. 칸 부족, `10:00` 형식, 짧은 요청 시각, 500건 초과가 모두 같은 메시지로 나와요.
- 인원은 파싱에 실패하면 조용히 0명이 돼요(:82-84, ROOM-19).
- `dayDiff`는 파싱에 실패하면 0을 돌려줘요(`RsvUtil.java:62`). 그러면 요청 시각이 엉터리여도 14일 검사를 통과해요.

### 7. 입력 처리의 함정
- 제목에 쉼표가 있으면 그 뒤가 잘려요(commands.txt 37행 → "주간 회의").
- 제목을 비우면 Java `split`이 끝의 빈 칸을 버려서 9칸이 돼요. 그러면 `arr[9]`에서 예외가 나서 "형식 오류"가 돼요.
- `chkRoom`은 이름이 정확히 같아야 해요. `중회의실 A`(공백)나 `r01`(소문자)은 "없는 회의실"이 돼요. 그리고 이 함수는 입력 배열 `arr`를 직접 고쳐요.

### 8. 소스에 비밀값이 있어요
- 주석 처리된 JDBC 연결(`RsvManager.java:29-32`)과 `sendSms`(:317-)에 접속 주소와 키가 그대로 적혀 있어요.
- 이 보고서에는 값을 옮기지 않았어요. 저장소를 밖으로 공유하기 전에 확인하세요. 진짜 값인지는 아직 확인하지 않았어요.

### 9. 그 밖
- 상태가 모두 static이고 초기화 코드가 없어요. 한 JVM에서 두 번 돌리면 상태가 섞여요.
- 화면 출력은 플랫폼 기본 인코딩을 따라요. Windows에서는 MS949로 나가요.
- `rpad`가 글자 수로 맞춰서 한글 칸이 어긋나요(보기 문제).

### 코드 안에서 어긋난 곳
- `arrRsv` 머리 주석은 9칸이라고 하지만 실제는 10칸이에요(1절 표).
- 주석 처리된 `insertRsv`(:34-)는 옛 9칸 배치를 따라요. DB를 다시 켜면 제목 대신 인원이 들어가요.
- `RsvUtil.isExec`(:118)는 `10001`도 임원으로 보지만 아무 데서도 부르지 않아요. 실제 검사(:107, :252)는 `startsWith("9")`만 봐요.
- 쓰지 않는 코드:
  - `Const`의 모든 값
  - `RsvUtil.isExec`, `RsvUtil.getNow`
  - `RoomInfo.getFloor`
  - `vHist`, `ST_DEL`
  - `sendSms`
- 코드는 숫자를 그 자리에 직접 써요(`180`, `14`, `"10001"`, `"A"`/`"C"`). R05의 `700`과 정원 `+2`는 `Const`에도 없어요.
