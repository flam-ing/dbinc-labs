# CLAUDE.md

이 저장소에서 작업하는 Claude Code를 위한 안내예요.

※ 교육용 가상 자료예요. 회사, 사람, 서버, 규정은 모두 지어낸 것이에요.

## 개요

총무팀 회의실 예약 요청 파일을 한 줄씩 처리해 예약표를 표준 출력으로 찍는 Java 배치(`com.nuri.room.RoomBatch`)예요. 2010년에 만들었고, 2010-07부터 DB 없이 파일만으로 돌아요.

- 운영: 봇이 그달 요청을 `D:\room\req\yyyyMM.txt`에 쌓고, 매일 밤 11시에 **그달 파일 전체를 처음부터 다시 처리**해요. 예약을 따로 저장하지 않아요.
- 그래서 예약번호(`R0001`…)는 매번 처리 순서대로 다시 매겨져요. 검사 규칙을 바꾸면 그 뒤 예약번호가 모두 밀리고, 그 번호를 가리키는 CXL/CHG 결과까지 달라져요.

## 빌드와 실행

    javac -encoding UTF-8 -d classes src/com/nuri/room/*.java
    java -cp classes com.nuri.room.RoomBatch data/commands.txt

- `-encoding UTF-8`을 꼭 붙여요(2012년에 MS949에서 바꿨어요).
- README의 `lib/ojdbc14.jar`, `conf/db.properties`는 저장소에 없고 필요 없어요. DB 코드는 주석 처리돼 있어요.
- 인자가 없으면 종료 코드 1, 파일을 못 열면 2예요.
- 운영 환경은 JDK 6이에요(기획서 기준). diamond, 람다, try-with-resources, 문자열 switch 같은 Java 7 이후 문법은 쓰지 마세요.
- `classes/`, `actual/`, `build/`는 `.gitignore`에 있어요.

## 테스트

자동 테스트는 없어요. `data/`의 요청 파일을 돌려서 고치기 전과 후의 출력을 비교해요.

    mkdir -p actual
    java -cp classes com.nuri.room.RoomBatch data/commands.txt > actual/commands.txt

| 파일 | 내용 | 지금 결과(마지막 줄) |
| --- | --- | --- |
| `commands.txt` | 2010-03-12~15 요청 38줄, 오류 줄 섞임 | 성공 19, 실패 19 |
| `month.txt` | 2010-04 한 달 치 325줄 | 성공 198, 실패 127 |
| `old-bot.txt` | 2009년판 봇 요청 7줄(회의실 이름, 세 자리 시각) | 성공 6, 실패 1 |
| `empty.txt` | 메모 한 줄뿐 | "예약 없음" |

의도하지 않은 줄의 결과가 바뀌었다면 위의 "예약번호가 밀리는" 효과인지 먼저 확인해요.

## 코드 구조 (`src/com/nuri/room/`)

- `RoomBatch` — main. 시간대를 서울로 고정하고, 빈 줄과 `#` 줄을 건너뛰며 `RsvManager.process`를 불러요. 끝나면 예약표와 건수를 찍어요.
- `RsvManager` — 명령 처리(`doReserve`, `doCancel`, `doChange`, `doQuery`). 상태는 모두 static 필드예요.
- `RsvPrinter` — 예약표 출력. 상태 `A`만 골라 날짜+회의실+시작 순으로 버블 정렬해요.
- `RsvUtil` — 날짜/시각 변환, 패딩, 회의실 이름→번호 변환(`chkRoom`은 `arr`를 직접 고쳐요).
- `RoomInfo` — 회의실 목록(소스에 하드코딩). R06은 2010-06에 없어져 주석 처리돼 있어요.
- `Const` — 상수지만 **대부분 쓰이지 않아요.** 코드는 숫자를 그 자리에 직접 적어요. `MAX_MIN=120`, `MAX_DAY=7`은 실제 동작(180분, 14일)과도 달라요. `Const`만 고쳐서는 동작이 바뀌지 않아요.

`arrRsv` 칸 구조는 javadoc이 틀렸어요. 실제로는 이래요.

    [0] 예약번호 [1] 회의실 [2] 날짜 [3] 시작 [4] 종료
    [5] 사번     [6] 이름   [7] 인원 [8] 제목 [9] 상태(A 정상, C 취소)

## 명령 형식

    RSV,요청시각,사번,이름,회의실,날짜,시작,종료,인원,제목
    CXL,요청시각,사번,예약번호
    CHG,요청시각,사번,예약번호,날짜,시작,종료
    QRY,요청시각,날짜

요청시각 `yyyyMMddHHmm`, 날짜 `yyyyMMdd`, 시각 `HHmm`. 명령은 대문자로 바꿔서 봐요(`rsv`도 돼요). HLD 같은 다른 명령은 "알 수 없는 명령"이에요.

## 고치기 전에 알아야 할 것

- **`TimeZone.setDefault(...)` 줄은 지우지 마세요.** 서버 시간대가 미국 서부라서, 없으면 서머타임 주에 날짜 차이가 하루 틀려요(2011-03 장애).
- `doReserve`와 `doChange`는 같은 검사를 복사해 따로 갖고 있어요. 한쪽만 고치면 어긋나요.
- CHG에 청소 시간 검사가 없는 건 **일부러 둔 거예요**(ROOM-12). 총무팀이 임원 점심 회의를 변경으로 넣어요. 총무팀 "강제 예약" 기능 없이 막지 마세요.
- 임원 판정은 각 검사에서 `startsWith("9")`로 직접 해요. `RsvUtil.isExec`는 아무 데서도 안 써요. 2012년 이후 임원은 사번이 1로 시작할 수 있어요(ROOM-31, 진행 중).
- 날짜와 시각을 문자열로 이어 붙여 비교해요. `930` 같은 세 자리 시각은 겹침 검사를 통과하고 `93:0`으로 찍혀요(ROOM-23). 숫자 비교로 고치면 기존 결과가 바뀌니 총무팀과 날을 잡아야 해요.
- 인원이 비거나 숫자가 아니면 0명으로 통과해요(ROOM-19, 해결 안 함).
- 칸을 쉼표로만 나눠요. 제목의 쉼표 뒤는 잘리고, 제목이 비면 "형식 오류"예요. 모든 예외는 "형식 오류"로 삼켜져요.
- 예약은 최대 500건(`new String[500][10]`)이에요. 넘으면 그 뒤가 모두 "형식 오류"가 돼요.
- 주석 속 DB 접속 코드와 `sendSms`(호출 안 함)는 옛 흔적이에요. 다시 살리지 마세요.
