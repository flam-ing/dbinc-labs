# 재고 발주 배치 지식베이스

재고 발주 배치(reorder)의 업무 규칙, 그 규칙의 이유, 위험한 곳을 팀이 같이 보려고 정리했어요. 코드(`src/`), 위키(`wiki/`), 이슈(`issues/`), 시험 자료(`data/`)를 읽고 2026-10-17에 만들었어요. 프로그램은 돌리지 않았고, 실행 결과 숫자는 `인수인계-보고서.md`에서 옮겼어요.

## 페이지

| 페이지 | 언제 읽나 | 담은 것 |
| --- | --- | --- |
| [지금 맞는 규칙](rules.md) | 발주 숫자가 왜 이렇게 나오는지 알고 싶을 때 | 계산 순서, 창고별 차이, **바뀐 값과 이유·출처**, 발주 파일 형식, 운영 |
| [위험한 곳](risks.md) | 코드를 고치기 전, 이상한 발주가 나왔을 때 | 건드리면 사고 나는 곳, 조용히 틀리는 곳, 배치가 멈추는 곳 |
| [위키·이슈 요약](wiki-issues.md) | 원본 문서를 읽기 전, 결정의 배경을 찾을 때 | 위키 5쪽과 이슈 5건 요약, 지금도 맞는 것과 낡은 것, 사람 |

## 먼저 알아 둘 것

1. **코드가 지금 동작이에요.** README·위키와 다르면 코드를 믿어요. 다만 부산 단종(INV-57)과 판매자료 오류 0줄(INV-80)은 문서가 의도이고 코드가 버그예요.
2. **창고마다 계산이 다른 건 대부분 일부러예요.** 이천만 평균 버림(INV-63), 부산 +1일, 제주 +3일. "통일"하려면 구매팀장 승인을 받아요.
3. **발주 파일 형식은 EDI 업체와의 계약이에요.** 열 순서, 헤더, `EOF`, CRLF, 따옴표 없음(INV-71)을 바꾸지 않아요.
4. **자동 테스트가 없어요.** 고치면 고치기 전과 후의 리포트와 발주 파일을 같은 입력으로 만들어 비교해요.
