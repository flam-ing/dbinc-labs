# 실습 1 결과 견본: kb 세 쪽

> 강사가 2026년 10월에 학생 자리와 같은 폴더(5교시를 마친 레거시 폴더)에서 Claude Code로 실제로 보내서 받은 답이에요. Claude가 한 말은 고치지 않았어요. 같은 문장을 보내도 답은 매번 조금씩 달라요.

만든 kb 파일 원문은 옆 폴더에 있어요. 같은 문장을 보냈는데 셋째 쪽 이름이 레거시마다 달랐어요(room-java는 `sources.md`, inventory-py는 `wiki-issues.md`). 쪽 이름은 Claude가 정하니 달라도 괜찮아요.

- [`kb-room-java/`](kb-room-java/): 회의실 예약. `rules.md`의 "운영 시간" 칸에 화상회의실(R05)이 7시에 여는 이유가 있어요.
- [`kb-inventory-py/`](kb-inventory-py/): 재고·발주. `rules.md`의 "바뀐 값과 이유" 표에 제주 가산이 3일로 늘어난 이유가 있어요.

## 회의실 예약(room-java)

- 모드: Accept edits
- 걸린 시간: 4분 2초, Claude와 도구가 28번 주고받았어요.

보낸 말:

```text
wiki/와 issues/와 코드를 읽고 docs/kb/에 팀이 같이 볼 지식베이스를 세 쪽으로 만들어 줘. 지금 맞는 규칙, 위험한 곳, 위키·이슈 요약으로 나누고, 바뀐 값마다 이유와 출처 파일을 같이 적어 줘. 목차 docs/kb/README.md도 만들고, CLAUDE.md에 "업무 규칙과 그 이유는 docs/kb/README.md부터 읽어" 한 줄을 더해 줘. 명령은 실행하지 말고, 원본은 고치지 마.
```

Claude의 답(원문 그대로):

````markdown
`docs/kb/`에 지식베이스 네 파일(목차와 세 쪽)을 만들었고, `CLAUDE.md`에 요청하신 한 줄을 더했어요. 프로그램은 빌드하거나 돌리지 않았어요. 다만 파일 목록을 보려고 `git ls-files`를 한 번 실행했어요(읽기만 하는 명령이에요). 원본 파일은 고치지 않았어요.

**만든 파일**

| 파일 | 내용 |
| --- | --- |
| `docs/kb/README.md` | 목차, "코드가 가장 최신"이라는 원칙, 출처를 적는 방식 |
| `docs/kb/rules.md` | 지금 맞는 규칙. 바뀐 값 7개(최대 3시간, 청소 12~13시, R05 07시, 14일, 정원+2, 임원, 취소·변경 권한)마다 현재 값, 코드 위치, 예전 값이 남은 곳, 바뀐 이유, 출처 `파일:줄`을 적었어요. 회의실 목록, 입력 형식, `arrRsv` 칸 배치, 운영 방식도 있어요. |
| `docs/kb/risks.md` | 위험한 곳 10개를 심각한 순서로, 고치면 안 되는 것, 고치기 전 체크리스트 |
| `docs/kb/sources.md` | 위키 5개와 이슈 5개 요약, 어느 문서가 최신인지, 지키지 않은 약속, 이유가 어디에도 적혀 있지 않은 것 |

`CLAUDE.md`에는 소개 문단 바로 아래에 이 줄을 넣었어요: "업무 규칙과 그 이유는 `docs/kb/README.md`부터 읽어."

**코드를 읽다 새로 찾은 것 (문서에 적혀 있지 않던 것)**

- **인수인계 보고서의 입력 형식이 틀렸어요.** `인수인계-보고서.md:46-48`의 칸 순서가 코드와 달라요. RSV는 사번·이름 위치가, CXL·CHG는 사번·예약번호 순서가 달라요. 맞는 순서는 코드와 기획서 4절 기준으로 `rules.md` 4절에 적었어요.
- **세 자리 시각(ROOM-23)은 다른 검사도 빠져나가요.** 이슈에는 겹침 검사 얘기만 있지만 세 가지가 더 있어요.
  - 대회의실 청소 검사: `930~1230` 예약이 청소 시간에 들어가요.
  - 지난 시간 검사: 요청한 날과 같은 날이면 이미 지난 09:00도 통과해요.
  - 예약표 정렬: 10시 예약보다 뒤에 찍혀요.
- **변경(CHG)의 3시간 검사는 예약한 사람이 아니라 변경을 요청한 사람의 사번을 봐요.** 그래서 총무팀(10001)이 임원의 4시간 예약을 다른 날로 옮기려 하면 "3시간 초과"가 나요.

이 세 가지는 코드만 읽고 판단한 것이고 실행해서 확인하지는 않았어요. `risks.md`에도 그렇게 적었어요.

**확인 부탁드릴 것**

- `CLAUDE.md`의 다른 문장은 "~해요" 말투인데, 더한 줄은 주신 문구 그대로 "읽어"로 끝나요. 맞추고 싶으시면 "읽어 주세요"로 바꿀게요.
- 쉼표만 있는 줄에서 배치가 멈춘다는 내용 같은 실행 결과는 이번에 다시 돌려 보지 않고 인수인계 보고서에서 가져왔어요. 그렇다고 출처를 달아 두었어요.
````

## 재고·발주(inventory-py)

- 모드: Accept edits
- 걸린 시간: 3분 19초, Claude와 도구가 32번 주고받았어요.

보낸 말:

```text
wiki/와 issues/와 코드를 읽고 docs/kb/에 팀이 같이 볼 지식베이스를 세 쪽으로 만들어 줘. 지금 맞는 규칙, 위험한 곳, 위키·이슈 요약으로 나누고, 바뀐 값마다 이유와 출처 파일을 같이 적어 줘. 목차 docs/kb/README.md도 만들고, CLAUDE.md에 "업무 규칙과 그 이유는 docs/kb/README.md부터 읽어" 한 줄을 더해 줘. 명령은 실행하지 말고, 원본은 고치지 마.
```

Claude의 답(원문 그대로):

````markdown
`docs/kb/`에 지식베이스 세 쪽과 목차를 만들었고, CLAUDE.md에 한 줄을 더했어요. 명령은 실행하지 않았고, 원본(코드, 위키, 이슈, README, 보고서)도 고치지 않았어요. 커밋은 하지 않았어요.

**만든 파일**
- `docs/kb/README.md`: 목차예요. 먼저 알아 둘 것 네 가지와, 질문별로 어느 쪽을 보면 되는지 정리한 "바로 찾기"가 있어요.
- `docs/kb/rules.md` (지금 맞는 규칙): 계산 순서, 창고별 차이, 발주 파일 형식, 운영 방식을 담았어요. "바뀐 값과 이유" 표는 항목마다 예전 값 → 지금 값, 바뀐 때, 이유, 출처 파일을 적었어요. 계수 1.65, 이천만 버림, 제주 3일, S03 박스 단위, UTF-8, FTP를 끈 일, 파이썬 3.6 등이에요. 그대로지만 이유가 있는 값(7일, 30일, 반품 건너뛰기, MOQ 주문)도 따로 모았어요.
- `docs/kb/risks.md` (위험한 곳): 네 갈래로 나눴어요. 건드리면 바로 사고 나는 곳, 틀린 결과를 조용히 내는 곳, 배치가 멈추거나 파일을 덮어쓰는 곳, 환경 문제예요.
- `docs/kb/wiki-issues.md` (위키·이슈 요약): 위키 5쪽은 "지금도 맞는 것"과 "낡은 것"으로 나눴어요. 이슈 5건은 상태와 결정을 표로 정리했고, 관련된 사람 목록도 넣었어요.
- `CLAUDE.md` 개요 목록에 "업무 규칙과 그 이유는 `docs/kb/README.md`부터 읽어요." 한 줄을 넣었어요.

**알아 두실 점**
- **실행 결과 숫자는 직접 확인하지 않았어요.** 빈 판매 파일일 때 2건, `BAD_LINES` 2 대 0 같은 숫자는 `인수인계-보고서.md`에서 옮겼고, 문서에 그렇다고 적어 두었어요.
- **파일 목록을 얻은 방법**: 파일을 찾는 도구가 없고 명령도 쓰지 않기로 해서 `.git/index`를 읽어 목록을 얻었어요.
- **시험 자료를 읽다가 보고서에 없는 두 가지를 찾았어요.** 실행해서 확인한 것은 아니에요. `risks.md` B-7, B-8에 넣었어요.
  - `data/sales.csv:182`의 `2015-10-32`는 없는 날짜인데, 문자열로 비교하면 기간 안이라 정상 판매로 더해져요.
  - `data/sales.csv:165-166`에 똑같은 줄이 두 번 있고 둘 다 더해져요. 실제로 두 번 팔린 것인지 중복 전송인지는 확인하지 못했어요.
- **CLAUDE.md와 보고서에 틀린 곳이 하나 있어요.** 두 문서 모두 `verify-out/`이 `.gitignore`에 있다고 하는데, 실제로는 없어요. 한 줄만 더하라고 하셔서 CLAUDE.md는 고치지 않았어요. `risks.md` D에만 적어 두었어요.
````
