# 포인트 배치 기획서 (1차 오픈)

| 공간 | 작성자 | 처음 작성 | 마지막 수정 |
| --- | --- | --- | --- |
| 커머스개발팀 › 기획 | 한동욱 | 2016-03-21 | 2017-08-07(서예진) |

※ 교육용 가상 자료예요. 회사, 사람, 정책은 모두 지어낸 것이에요.

누리몰 멤버십 포인트 1차 오픈(2016년 4월)을 앞두고 쓴 기획서예요. 정책은 마케팅팀 공간의 "누리몰 멤버십 포인트 정책"을 따라요. 맨 아래 8절은 2017년에 서예진이 덧붙였어요.

## 1. 왜 만드나요

2016년 4월에 누리몰 멤버십 포인트를 시작해요. 몰 결제 시스템은 결제와 포인트 사용만 처리하고, 적립과 소멸 계산은 하지 않아요. 그래서 포인트 배치가 날마다 회원별 적립, 사용, 소멸을 계산하고, 곧 사라질 포인트를 회원에게 알려요.

## 2. 쓰는 사람

| 누구 | 하는 일 |
| --- | --- |
| 회원 | 소멸 예정 안내 메일을 받아요 |
| 마케팅팀 | 적립률과 프로모션을 정해요 |
| CS팀 | 고객 문의 때 배치 결과로 적립 내역을 확인하고, 수동 조정을 넣어요 |
| 재무회계팀 | 매달 말일 기준 잔액 합계를 포인트 부채로 잡아요 |
| 몰 개발팀 | 거래와 회원 자료를 주고, 몰 화면에 잔액을 보여 줘요 |

## 3. 주요 기능

### 적립

- 구매(BUY)마다 적립해요. 기준 금액은 결제 금액에서 부가세를 뺀 공급가액이에요. 결제 금액을 1.1로 나눠서 구해요. 재무회계팀이 요청한 기준이에요.
- 공급가액에 등급별 적립률을 곱하고, 1점 미만은 버려요.

| 등급 | 적립률 |
| --- | --- |
| NORMAL(일반) | 1% |
| VIP | 2% |
| STAFF(임직원) | 적립 없음 |

- 등급은 회원 자료에 있는 지금 등급을 써요. 비어 있으면 일반으로 봐요.
- 프로모션 기간에는 적립률을 몇 배로 올려요. 기간과 배수는 마케팅팀이 정해 주면 코드에 넣어요. 설정 파일은 2차에서 만들어요.

### 사용

- 몰 결제 화면에서 쓴 포인트(USE)를 받아서, 먼저 적립한 포인트부터 빼요.
- "100점부터 사용"과 "가진 포인트보다 많이 쓰지 못함"은 몰 결제 화면이 막아요. 배치는 들어온 사용을 그대로 빼요.

### 구매 취소

- 구매를 취소(CANCEL)하면 그 주문(order_no)으로 적립한 포인트를 회수해요.
- 회원이 그 포인트를 이미 썼으면 남은 다른 포인트에서 빼요.
- 다른 포인트도 모자라면 잔액을 마이너스로 두고, 다음에 적립되는 포인트로 메워요.

### 수동 조정

- CS팀이 몰 관리 화면에서 넣는 조정(ADJ)을 반영해요. 더하는 조정은 새 적립처럼 그날부터 소멸 기간을 세요. 빼는 조정은 먼저 적립한 포인트부터 빼요.

### 소멸

- 포인트는 적립일로부터 1년이 지나면 소멸해요.
- 기준일까지 소멸한 포인트는 잔액에서 빼고 소멸 칸에 적어요.

### 소멸 예정 안내

- 기준일부터 30일 안에 소멸할 포인트가 있으면 회원에게 안내 메일을 보내요.
- 광고 수신에 동의한 회원(ad_agree가 Y)에게만 보내요.
- 메일 주소가 없는 회원에게는 문자로 보내요. 문자 서버 연동은 오픈 뒤에 붙여요.
- 같은 회원에게는 한 달에 한 번만 보내요.

### 날마다 처음부터 다시 계산

1차에서는 적립 내역을 따로 저장하는 표(원장)를 만들지 않아요. 날마다 모든 거래를 처음부터 다시 읽어서 계산해요. 같은 입력과 같은 기준일이면 언제 돌려도 같은 결과가 나와요.

## 4. 입력

배치가 몰 DB의 회원 표와 거래 표를 직접 읽어요. 몰 DB 읽기 계정은 몰 개발팀에 신청해 두었어요.

거래 자료의 칸이에요.

| 칸 | 뜻 |
| --- | --- |
| tx_id | 거래 번호 |
| member_id | 회원 번호 |
| tx_dt | 거래 시각(`yyyy-MM-dd HH:mm:ss`) |
| type | BUY 구매, USE 사용, CANCEL 구매 취소, ADJ 수동 조정 |
| amount | BUY와 CANCEL은 결제 금액(원), USE와 ADJ는 포인트. ADJ는 빼는 조정이면 마이너스 |
| order_no | 주문 번호. BUY와 CANCEL에만 있어요 |

회원 자료의 칸이에요.

| 칸 | 뜻 |
| --- | --- |
| member_id | 회원 번호 |
| name | 이름 |
| grade | 등급. NORMAL, VIP, STAFF를 대문자로 적어요 |
| email | 메일 주소 |
| join_dt | 가입일 |
| ad_agree | 광고 수신 동의(Y 또는 N) |

기준일은 실행할 때 `yyyy-MM-dd`로 받아요. 주지 않으면 오늘 날짜를 써요. 기준일보다 뒤에 일어난 거래는 계산에서 빼요.

예) 거래 `T0101,M1001,2016-04-15 12:30:00,BUY,44000,O160415-001`
회원 M1001이 4월 15일에 44,000원을 결제한 구매예요. 공급가액이 40,000원이라 일반 회원이면 400점, VIP면 800점이 쌓여요.

## 5. 출력

- 화면(표준 출력): 회원마다 한 줄씩 적립, 사용, 회수, 조정, 소멸, 잔액, 소멸 예정 포인트를 찍고, 맨 아래에 합계를 찍어요. 재무회계팀은 말일 기준 합계의 잔액을 써요.
- 소멸 예정 안내 메일 파일: outbox 폴더에 회원마다 `EXP_yyyyMM_회원번호.txt`를 만들어요. 사내 메일러가 5분마다 outbox를 읽어서 보내요. 메일러는 한 번 보낸 파일 이름을 다시 보내지 않아요. 그래서 이름에 "달"만 넣어서 한 달에 한 번만 나가게 해요.

## 6. 운영

- 배치 서버에서 매일 새벽 3시에 돌려요(`run.bat`).
- Java 8로 만들어요.
- 결과가 이상하면 CS팀이 커머스개발팀 담당자에게 알려요.

## 7. 하지 않는 것

- 결제와 포인트 사용 처리는 하지 않아요. 몰 결제 시스템이 해요.
- 등급(VIP 기준) 산정은 하지 않아요. 마케팅팀 기준으로 몰이 정한 등급을 그대로 써요.
- 적립 내역 원장 저장은 2차에서 해요.
- 포인트 선물, 현금 전환은 없어요.
- 몰 화면에 잔액을 보여 주는 일은 몰 개발팀이 맡아요.

## 8. 시험용 파일 (data 폴더) — 2017-08-07 서예진 덧붙임

위 1~7절은 2016년 3월 기획 그대로예요. 그 뒤에 바뀐 것은 재무회계팀 페이지, 운영 페이지, 장애 보고, 이슈를 같이 봐요. 입력은 오픈 때부터 몰 개발팀이 새벽 2시에 뽑아 주는 CSV 두 개예요(운영 페이지 참고). 칸은 4절 표와 같고, 첫 줄은 칸 이름이에요.

코드를 고치기 전후로 결과를 비교하려고 만든 파일이에요. 실행할 때 인자는 거래 CSV, 회원 CSV, 기준일, 알림 폴더 순서예요.

    java -Dfile.encoding=UTF-8 -cp bin com.nuri.mall.point.PointBatch data/transactions.csv data/members.csv 2017-01-31 out/outbox

| 파일 | 무엇 |
| --- | --- |
| `transactions.csv` | 손으로 만든 거래 46줄이에요(2015-12부터 2017-02까지). 프로모션, 취소, 수동 조정, 운영에서 실제로 나왔던 이상한 줄이 섞여 있어요. 기준일 2017-01-31, 2017-03-01, 2016-10-07로 돌려 봐요 |
| `members.csv` | 위 거래의 회원 10명이에요 |
| `empty-tx.csv` | 칸 이름 줄만 있는 거래 파일이에요. 거래가 하나도 없을 때를 봐요 |
| `year/transactions.csv` | 회원 40명의 1년 넘는 거래 770줄이에요(2015-07부터 2017-07까지). 기준일 2017-06-30으로 돌려요 |
| `year/members.csv` | 위 거래의 회원 40명이에요 |

`transactions.csv` 예) `T0006,M1001,2016-02-20 15:45:00,BUY,33000,O160220-003`
거래 T0006은 회원 M1001이 2016년 2월 20일 15시 45분에 주문 O160220-003으로 33,000원을 결제한 구매예요.

`transactions.csv`의 사용 예) `T0009,M1001,2016-03-05 13:10:00,USE,500,`
회원 M1001이 3월 5일에 500점을 썼어요. 사용이라 주문 번호 칸이 비어 있어요.

`members.csv` 예) `M1001,김민준,VIP,minjun.kim@example.com,2014-03-02,Y`
회원 M1001 김민준은 VIP이고, 메일 주소가 있고, 2014-03-02에 가입했고, 광고 수신에 동의했어요.

`empty-tx.csv` 예) `tx_id,member_id,tx_dt,type,amount,order_no`
이 한 줄뿐이에요. 회원은 모두 0점으로 나와요.

`year/transactions.csv` 예) `T100001,M2018,2015-07-01 18:12:35,BUY,88000,O150701-0001`
회원 M2018이 2015년 7월 1일에 88,000원을 결제한 구매예요.

`year/members.csv` 예) `M2001,권승호,STAFF,staff2001@nuri.example,2014-12-01,Y`
회원 M2001 권승호는 임직원(STAFF)이라 적립이 없어요.
