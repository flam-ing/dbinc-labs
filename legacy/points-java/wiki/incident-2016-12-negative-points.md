# [장애 보고] 2016-12-03 마이너스 포인트 회원 결제 불가

| 공간 | 작성자 | 처음 작성 | 마지막 수정 |
| --- | --- | --- | --- |
| 커머스개발팀 › 장애 보고 | 최승우 | 2016-12-05 | 2016-12-09 |

※ 교육용 가상 자료예요. 회사, 사람, 숫자는 모두 지어낸 것이에요.

## 요약

| 항목 | 내용 |
| --- | --- |
| 일시 | 2016-12-03(토) 10:00 ~ 13:10 |
| 영향 | 회원 12명이 결제 화면에서 오류를 보고 결제하지 못했어요. |
| 원인 | 포인트 배치가 구매 취소 때 포인트를 회수하면서 잔액을 0 밑으로 내렸어요. 결제 화면은 잔액이 0 이상이라고 가정하고 있었어요. |
| 조치 | 배치가 잔액을 0 밑으로 내리지 않게 바꿨어요(12-05 배포). |

## 무슨 일이 있었나요

구매를 취소하면 그 구매로 적립한 포인트를 회수해요. 그런데 회원이 그 포인트를 이미 써 버렸다면, 배치는 다른 포인트에서 모자란 만큼을 빼요. 다른 포인트도 모자라면 잔액을 마이너스로 두었어요. 12월 3일 아침 배치 뒤에 마이너스 잔액이 된 회원 12명이 결제 화면에 들어가자 오류가 났어요.

## 바꾼 것

1. 회수할 포인트가 모자라면 0까지만 빼요. 회수하지 못한 포인트는 CS팀에 알림 파일(`CS_거래번호.txt`)로 보내요. CS팀이 고객과 연락해서 처리해요(다음 구매 때 차감, 또는 회수 포기).
2. 사용 요청이 잔액보다 크면 사용을 거부하고, 마찬가지로 CS 알림 파일을 만들어요. 몰 화면에서는 이런 요청이 나오면 안 되므로, 이 알림이 오면 몰 쪽 잔액과 배치 쪽 잔액이 어긋난 것이에요.
3. 결제 화면에서도 마이너스 잔액을 막는 작업은 몰 개발팀이 따로 일정을 잡았어요.

## 지난 비슷한 장애

2016-09-19에 몰 결제 서버가 같은 거래를 두 번 보내서, 한 구매에 포인트가 두 번 쌓인 일이 있었어요. 그 뒤로 배치는 같은 거래 번호(tx_id)가 두 번 나오면 두 번째 줄을 건너뛰어요.
