# 포인트 배치 운영

| 공간 | 작성자 | 처음 작성 | 마지막 수정 |
| --- | --- | --- | --- |
| 커머스개발팀 › 운영 | 한동욱 | 2016-04-20 | 2017-01-24(서예진) |

※ 교육용 가상 자료예요. 회사, 사람, 서버는 모두 지어낸 것이에요.

## 1. 하루 흐름

1. 새벽 2시에 몰 개발팀 작업이 몰 DB의 전체 거래와 회원을 CSV 두 개로 뽑아요.
2. 새벽 3시에 포인트 배치가 돌아요. 원장(적립 내역을 저장하는 표)이 없어서, 날마다 모든 거래를 처음부터 다시 계산해요.
3. 배치는 회원별 표를 화면(표준 출력)에 찍고, 알림 파일을 outbox 폴더에 만들어요.
4. 메일러(사내 메일 발송 프로그램)가 5분마다 outbox 폴더를 읽어서 메일을 보내요.

## 2. 실행

배치 서버의 `C:\points\data\`에 `transactions.csv`와 `members.csv`를 두고 `run.bat`을 실행해요. 인자 없이 실행하면 이 폴더를 써요.

    java -Dfile.encoding=UTF-8 -cp bin com.nuri.mall.point.PointBatch

`-Dfile.encoding=UTF-8`은 꼭 붙여요. 빼면 알림 파일의 한글이 깨져요. 알림 파일을 쓰는 코드가 서버의 기본 인코딩을 따르기 때문이에요.

## 3. 알림 파일 이름 규칙 (바꾸지 마세요)

| 파일 이름 | 받는 곳 | 내용 |
| --- | --- | --- |
| `EXP_yyyyMM_회원번호.txt` | 회원 메일 | 30일 안에 소멸될 포인트 안내 |
| `CS_거래번호.txt` | CS팀 메일함 | 회수 부족, 사용 거부 확인 요청 |

메일러는 한 번 보낸 파일 이름을 기억하고, 같은 이름의 파일은 다시 보내지 않아요. 배치는 날마다 처음부터 다시 계산하니까 같은 알림 파일을 날마다 다시 만들어요. 그래서 소멸 예정 안내는 이름에 "달"만 넣어서 한 달에 한 번만 나가게 하고, CS 알림은 거래 번호로 이름을 지어서 거래 하나에 한 번만 나가게 했어요.

2016년 11월에 소멸 예정 안내 파일 이름에 날짜(yyyyMMdd)를 넣었다가, 사흘 동안 같은 회원에게 같은 메일이 날마다 나간 적이 있어요. 이름 규칙을 바꿔야 하면 메일러 담당자와 먼저 이야기해요.

## 4. 프로모션 넣는 법

프로모션 기간과 배율은 PointService 코드에 직접 넣어요. 설정 파일은 아직 없어요.

- 2016 창립 기념 주간(10/1~10/7): 2016-10 한동욱
- 2017 설 연휴(1/26~1/30): 2017-01-24 서예진. 마지막 날도 포함되게 날짜로 비교했어요. 창립 기념 주간 코드는 PNT-41 때문에 손대지 않았어요.
