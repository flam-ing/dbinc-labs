> 공지봇을 처음 만들 때 쓴 기획서예요. 2016년 계획을 그대로 남겨 둬서 지금 동작과 다른 곳이 있어요. 지금 규칙은 "공지봇 발송 규칙" 페이지를 보세요. 맨 아래 "시험 자료" 절은 2022년에 더했어요.

## 목적

지금은 총무팀이 공지를 사내 포털 게시판에 올린 뒤, 같은 내용을 부서별 메일 주소록으로 다시 보내요. 주소록을 손으로 고치다 보니 부서를 옮긴 사람이 빠지고, 퇴사한 사람에게 가기도 해요. 공지를 올린 사람이 밤늦게 메일을 보내는 일도 있어요.

공지봇은 포털에 올라온 공지와 인사 시스템의 직원 목록을 읽어서 "누구에게, 몇 시에 보낼지"를 정한 메시지 목록을 만들어요. 주소록은 인사 시스템에서 매일 새로 받으니까 사람이 고칠 일이 없어요.

## 쓰는 사람

| 누구 | 무엇을 하나요 |
| --- | --- |
| 총무팀, 인사팀, 시설팀 | 포털의 공지 등록 화면에 공지를 올려요. 받는 부서와 보낼 시각을 정해요. |
| 직원 | 공지 메일을 받아요. |
| 총무팀 시스템 담당 | 공지봇을 만들고 운영해요. |
| IT팀 | 발송 게이트웨이를 운영해요. 게이트웨이가 공지봇이 만든 목록을 읽어서 실제로 메일을 보내요. |

## 주요 기능

1. 공지 파일과 직원 파일을 읽어요.
2. 공지마다 받는 부서에 속한 직원을 골라요. 받는 부서가 `ALL`이면 전 직원이에요. 퇴사한 직원은 빼요.
3. 직원마다 메일을 한 통씩 만들어요.
   - 제목은 "[누리상사 공지] 공지 제목"이에요. 긴급 공지는 "[긴급] 공지 제목"이에요.
   - 본문 맨 앞에 "OOO님, 안녕하세요."를 붙이고, 끝에 발신 전용 안내와 총무팀 내선 번호를 붙여요.
4. 보낼 시각을 정해요.
   - 예약 시각이 있으면 그 시각에 보내요. 예약 시각이 없거나 이미 지났으면 지금 보내요.
   - 일반 공지가 업무시간(평일 9시부터 18시 전까지) 밖이면 업무시간에 맞춰 미뤄요. 9시 전이면 그날 9시, 18시 뒤나 주말이면 다음 평일 9시에 보내요.
   - 긴급 공지는 업무시간과 상관없이 정한 시각에 바로 보내요.
   - 공휴일은 1단계에서 따지지 않아요. 휴일 목록을 받을 곳이 아직 없어요. 휴일 목록이 생기면 2단계에서 넣어요.
5. 같은 공지 번호가 파일에 두 번 들어오면 한 번만 보내요.
6. 만든 메일을 보낼 시각과 함께 outbox 폴더에 써요.

## 입력 파일

| 파일 | 누가, 언제 만드나요 |
| --- | --- |
| 공지 파일 (`notices.json`) | 포털의 공지 등록 화면이 매일 밤 다음 날 공지를 내보내요. |
| 직원 파일 (`employees.json`) | 인사 시스템이 매일 새벽에 내보내요. |
| 기준 시각 | 파일이 아니라 실행할 때 넣는 값이에요. 크론이 지금 시각을 넣어 줘요. |

공지 파일은 공지 하나가 JSON 객체 하나예요. 칸은 아래와 같아요.

| 칸 | 뜻 | 예 |
| --- | --- | --- |
| id | 공지 번호 | N-2016-007 |
| title | 제목 | 4월 소방 점검 안내 |
| body | 본문 | |
| target | 받는 부서 이름을 쉼표로 나눠서 적어요. 전 직원이면 `ALL`이에요. 쉼표 뒤에 띄어쓰기를 넣지 않아요. | 영업1팀,재무팀 |
| send_at | 예약 시각. 비우면 바로 보내요. | 2016-04-20 09:00 |
| urgent | 긴급이면 true, 아니면 false | false |
| author | 올린 부서 | 총무팀 |

직원 파일은 직원 한 명이 JSON 객체 하나예요. 칸은 사번(empNo), 이름(name), 부서(dept), 메일 주소(email), 재직 여부(active)예요. active가 false이면 퇴사한 사람이에요.

### 시험 자료 (`data/` 폴더)

2022-03 김도윤 추가: 누리톡으로 바꾸면서 저장소의 `data/` 폴더에 시험용 파일을 넣어 뒀어요. 지금 공지봇은 휴일 파일과 출력 폴더도 받아요. 기준 시각 2022-03-14T08:50으로 돌려 보면 돼요.

| 파일 | 무엇인가요 | 한 줄 예 | 이 줄의 뜻 |
| --- | --- | --- | --- |
| `data/notices.json` | 2022년 3월 공지 13개예요. 2019년 새 양식(depts, sendAt, level)과 시설팀이 아직 쓰는 2016년 옛 양식(target, send_at, urgent)이 섞여 있어요. | `"sendAt": "2022-03-14 08:30",` | 3월 정기 소방 점검 공지(N-2022-030)를 3월 14일 8시 30분에 보내도록 예약했다는 뜻이에요. |
| `data/employees.json` | 직원 12줄이에요. 직원마다 받는 채널(messenger는 누리톡, mail은 메일, sms는 문자)이 있어요. | `{ "empNo": "E1001", "name": "김민준", "dept": "영업1팀", "channels": ["messenger", "mail"], "email": "e1001@nuri.example", "phone": "010-0000-1001", "active": true },` | 영업1팀 김민준은 누리톡과 메일로 공지를 받고, 지금 다니는 직원이에요. |
| `data/holidays.json` | 총무팀이 만든 2022년 휴일 목록이에요. 양식은 "휴일 파일 관리" 페이지에 있어요. | `{ "date": "2022-03-01", "name": "삼일절" },` | 3월 1일은 삼일절이라 쉬는 날이에요. |
| `data/notices-empty.json` | 빈 목록 `[]` 한 줄이에요. | `[]` | 보낼 공지가 하나도 없는 날을 흉내 낸 파일이에요. |

시험 자료에는 운영에서 실제로 본 모양도 넣어 뒀어요. 같은 공지가 두 번 들어온 경우, 겸직자(같은 사번이 부서마다 한 줄씩), 퇴사자, 날짜를 잘못 쓴 공지와 휴일 같은 것이에요.

## 출력

- outbox 폴더에 보낼 메일 목록을 JSON 파일 하나로 써요. 메일마다 받는 사람 사번, 메일 주소, 공지 번호, 보낼 시각, 제목, 본문이 들어가요.
- 발송 게이트웨이가 이 목록을 읽어서, 보낼 시각이 지난 메일을 보내요.
- 실행할 때마다 몇 건을 만들었는지 화면(크론 로그)에 남겨요.

## 운영

- 총무팀 서버의 크론이 10분마다 실행해요.
- 실행 명령은 `node bot.js notices.json employees.json 2016-04-20T09:00` 모양이에요. 마지막 값이 기준 시각이에요.
- outbox 폴더는 `/home/notice/outbox`예요. 게이트웨이와 같이 쓰는 폴더라서 `config.js`에 적어 둬요.
- 운영 서버의 `config.js`는 서버에서 직접 고쳐서 써요. 배포할 때 덮어쓰지 않아요.
- 서버를 옮겨도 시각이 똑같이 나오게, 날짜 계산은 시간대를 타지 않는 방식으로 해요.
- 파일을 못 읽으면 크론 로그에 이유를 남기고 끝나요.
- 문의는 총무팀 박준호(내선 2041)에게 해요.

## 하지 않는 것

- 메일을 직접 보내지 않아요. 보내는 일은 IT팀 발송 게이트웨이가 해요.
- 메일 말고 다른 채널(쪽지, 문자)은 1단계에서 하지 않아요.
- 공휴일은 따지지 않아요(위 4번).
- 받은 사람이 읽었는지 확인하지 않아요.
- 공지를 쓰거나 승인하는 화면은 만들지 않아요. 포털의 공지 등록 화면을 그대로 써요.
- 첨부 파일은 보내지 않아요. 본문에 포털 게시판 위치를 적어 주세요.
- 부서가 아니라 사람 한 명 한 명을 골라서 보내지는 않아요.
