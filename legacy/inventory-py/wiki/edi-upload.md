# 공급처 EDI 발주 파일 규격

| 공간 | 물류·구매 (LOGI) |
| --- | --- |
| 작성자 | 최지훈 (물류팀) |
| 만든 날 | 2012-04-02 |
| 마지막 수정 | 2013-01-15, 최지훈 |
| 라벨 | EDI, 발주파일 |

> 교육용 가상 자료예요. 회사, 사람, 상품, 금액은 모두 지어낸 것이에요.

EDI는 공급처와 발주서를 파일로 주고받는 외부 업체의 시스템이에요. 발주 배치가 만든 파일을 EDI에 올리면 공급처마다 주문이 나뉘어 들어가요. 파일 모양은 EDI 업체와 계약할 때 정했어요. 우리가 마음대로 바꿀 수 없어요.

## 파일 모양

- 파일 이름은 `PO_YYYYMMDD.csv`예요. 날짜는 발주 기준일이에요.
- 글자 인코딩은 CP949예요.
- 줄바꿈은 CRLF(윈도우 방식)예요.
- 첫 줄은 열 이름이에요. 열 이름도 바꾸면 안 돼요.
- 마지막 줄은 `EOF` 세 글자예요.

## 열 순서

| 순서 | 열 | 내용 |
| --- | --- | --- |
| 1 | PO_DATE | 발주 기준일(YYYYMMDD) |
| 2 | WH | 받을 창고 코드 |
| 3 | SKU | 상품코드 |
| 4 | ITEM_NAME | 상품명. EDI는 읽지 않고 화면에 보여 주기만 해요. |
| 5 | SUPPLIER | 공급처 코드 |
| 6 | ORDER_QTY | 주문 수량 |
| 7 | UNIT_COST | 단가(원) |
| 8 | AMOUNT | 금액(원). 수량 × 단가 |

EDI는 열 이름이 아니라 열의 위치로 값을 읽어요. 열 순서를 바꾸면 수량 자리에 단가가 들어가는 식으로 주문이 틀어져요.

## EOF 줄이 꼭 있어야 하는 이유

EDI 업로드 프로그램은 파일 마지막 줄이 `EOF`가 아니면 전송 중에 끊긴 파일로 보고 파일 전체를 버려요. 오류 메일도 오지 않아요. 2012년 6월에 EOF 줄을 빠뜨린 파일을 올려서 그날 발주가 통째로 들어가지 않은 일이 있었어요. 이틀 뒤 공급처 전화를 받고서야 알았어요.

## 올리는 방법

발주 배치가 매일 07:20에 FTP로 EDI에 자동으로 올려요. 08:00까지 EDI 화면에 파일이 보이지 않으면 구매팀이 EDI 웹 화면에서 직접 올려요.
