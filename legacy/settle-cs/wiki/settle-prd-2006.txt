[기획서] 매장 일일 정산 배치 (DailySettle)
2006.02.20 작성  박 대리 (전산)   검토: 정산팀, 물류팀, 김 과장(DBA)
※ 교육용 가상 자료입니다. 회사, 매장, 상품, 금액은 모두 가상입니다.

------------------------------------------------------------
1. 목적
------------------------------------------------------------
 - 지금은 정산팀이 아침마다 매장별 POS 마감 리포트를 엑셀에 옮겨 적고, 카드 수수료를 손으로 계산한다.
   매장이 5개로 늘면서 정산이 오전 내내 걸린다.
 - POS가 밤에 떨구는 주문 파일을 배치가 읽어서 매장별 하루 정산표를 자동으로 만든다.
 - ERP에 올릴 정산 숫자도 같이 만든다. DBA가 그대로 복사해서 실행할 수 있는 모양으로 만든다.
 - 같은 입력이면 언제 돌려도 같은 결과가 나와야 한다. 지난 날짜를 다시 정산할 일이 있기 때문이다.

------------------------------------------------------------
2. 쓰는 사람
------------------------------------------------------------
 - 정산팀: 아침에 정산표를 메일로 받아 확인한다.
 - 김 과장(DBA): 출력 맨 아래의 INSERT 문을 복사해서 ERP DB에 실행한다.
 - 물류팀: 재고 부족 목록을 보고 발주한다.
 - 전산(박 대리): 배치를 만들고 운영한다.

------------------------------------------------------------
3. 주요 기능
------------------------------------------------------------
3-1. 영업일 주문 고르기
 - 실행할 때 영업일(yyyy-MM-dd)을 받는다. 주문 시각이 그 영업일인 주문만 정산한다.
 - 22시 이후 주문은 다음 날 매출로 넣는다. 택배사 마감이 22시라서 그 뒤 주문은 다음 날 나가기 때문이다.
 - 주문 파일에는 앞뒤 날짜 주문이 섞여 올 수 있다. 그래서 파일 이름이 아니라 주문 시각으로 다시 고른다.
 - 메모에 TEST가 들어간 주문은 매장 직원 교육용이라서 뺀다.
 - 매장 코드표(3-5)에 없는 매장의 주문은 뺀다.
 - 읽을 수 없는 줄은 건너뛴다. 배치가 주문 파일을 고쳐서 읽지는 않는다.

3-2. 주문 상태
 - OK(판매): 매출(SALES)에 넣고 판매 건수(CNT)를 센다.
 - RTN(반품): 반품(RETURN)에 넣는다. 원래 주문 날짜와 상관없이 반품을 처리한 날의 매출에서 뺀다.
 - CXL(취소): 정산하지 않는다.

3-3. 결제 수단과 수수료
 - 판매 금액을 결제 수단별로 CARD(카드), CASH(현금), POINT(포인트) 칸에 나눠 더한다.
   반품은 결제 수단 칸에 넣지 않고 RETURN 칸에만 넣는다.
 - 카드 수수료(FEE)는 카드 매출의 2.5%다. 2006년 카드사 계약 요율이다.
 - 수수료는 원 단위로 반올림한다. 카드사 정산 파일과 1원까지 맞아야 하므로 반올림 방식은 회계팀에 확인해서 맞춘다.
 - 포인트 결제는 수수료가 없다. 포인트로 산 것도 매출에 들어간다.
 - 순매출(NET)은 매출에서 반품과 수수료를 뺀 금액이다.

3-4. 재고 부족 목록
 - 상품 파일의 재고(전날 마감 재고)에서 오늘 판매 수량을 빼고, 오늘 반품 수량을 더한다.
 - 남는 수량이 기준보다 적은 상품을 재고 부족 목록에 찍는다. 기준은 물류팀이 정한다. 1차는 3개로 시작한다.
 - 상품 파일에 없는 상품은 매출에는 넣고 재고 계산에서는 뺀다.

3-5. 매장 코드표
   ST01 본점 / ST02 신촌점 / ST03 대학로점 / ST04 역삼점 / ST05 역전점
 - 1차는 매장 코드표를 소스 안에 둔다. 매장이 생기거나 닫으면 2차에서 설정 파일(stores.ini)로 뺀다.

------------------------------------------------------------
4. 입력 파일
------------------------------------------------------------
4-1. 주문 파일
 - POS 업체가 매일 밤 D:\pos\ 에 떨군다. 이름은 orders_yyyyMMdd.csv 이다.
 - 첫 줄은 제목 줄이다. 칸은 쉼표로 나눈다. 칸 순서는 POS 업체와 정한 것이라 바꾸지 않는다.

   칸           뜻
   order_id     주문 번호
   order_dt     주문 시각 (yyyy-MM-dd HH:mm)
   store        매장 코드 (ST01 같은 것)
   pay          결제 수단 (CARD, CASH, POINT)
   sku          상품 코드 (상품 파일의 sku)
   qty          수량
   unit_price   한 개 값 (원, 쉼표 없이)
   status       OK 판매, RTN 반품, CXL 취소
   memo         매장 직원이 남긴 메모 (비어 있어도 된다)

   예) 0007,2006-02-17 10:15,ST02,CASH,A-200,1,4580,OK,
       신촌점에서 2월 17일 10시 15분에 상품 A-200을 1개, 4,580원에 현금으로 판 주문이다. 메모는 없다.

4-2. 상품 파일
 - 물류팀이 매일 밤 마감 재고로 새로 만든다. 이름은 products.csv 이다.

   칸      뜻
   sku     상품 코드
   name    상품 이름
   stock   전날 마감 재고 수량

   예) A-200,라면 5입,25
       상품 A-200(라면 5입)의 전날 마감 재고가 25개라는 뜻이다.

------------------------------------------------------------
5. 출력
------------------------------------------------------------
 모두 화면(표준 출력)에 찍는다. 스케줄러가 받아서 정산팀에 메일로 보낸다.
 - 정산표: 맨 위에 "DAILY SETTLEMENT 영업일" 제목.
   매장마다 한 줄, 칸은 STORE, CNT, SALES, RETURN, CARD, CASH, POINT, FEE, NET 순서다. 맨 아래 TOTAL 줄.
   정산팀 엑셀 양식(정산표_양식_v3.xls)과 칸 순서를 맞춘다.
 - 재고 부족 목록: 상품 코드와 남는 수량. 없으면 (none).
 - ERP 업로드용 INSERT 문: "-- ERP UPLOAD" 줄과 "-- END" 줄 사이에 매장마다 한 줄.
   INSERT INTO TB_DAILY_SETTLE (BIZ_DT, STORE_CD, SALES_AMT, RTN_AMT, FEE_AMT, NET_AMT) VALUES (...);
   DBA가 그대로 실행하므로 숫자에 쉼표를 넣지 않는다.
 - 실행 기록은 D:\batch\settle\log\ 에 날짜별로 남긴다.

------------------------------------------------------------
6. 운영
------------------------------------------------------------
 - 서버: 배치서버 1호기 D:\batch\settle\
 - 작업 스케줄러 DAILY_SETTLE, 매일 06:00. 영업일은 어제 날짜다.
 - 명령: DailySettle.exe <주문 CSV> <상품 CSV> <영업일 yyyy-MM-dd>
 - 종료 코드: 0 정상, 1 인자 부족, 2 파일 없음, 9 그 밖의 오류.
   0이 아니면 스케줄러가 정산팀에 메일을 보낸다.
 - 지난 날짜를 다시 정산할 때는 그날의 주문 파일과 날짜를 넣어 손으로 다시 돌린다.
 - 개발 환경: Visual Studio 2005, .NET Framework 2.0

------------------------------------------------------------
7. 하지 않는 것 (1차 범위 밖)
------------------------------------------------------------
 - ERP DB에 직접 넣지 않는다. INSERT 문만 만들고 실행은 DBA가 한다.
 - 발주는 하지 않는다. 재고 부족 목록만 보여 준다.
 - 카드사 정산 파일과 맞춰 보는 일은 회계팀이 한다.
 - 수수료율, 재고 기준, 매장 코드표를 화면에서 바꾸는 기능은 만들지 않는다.
 - 품목마다 다른 재고 기준은 두지 않는다.
 - 주문 파일이 틀렸을 때 고치는 일은 하지 않는다. POS 파일은 POS 업체가 책임진다.

위 본문은 2006년 기획서를 그대로 둔 거예요. 본문은 고치지 않았어요.
그 뒤에 바뀐 것은 인수인계 메모, 장애 메모, 이슈를 같이 봐요.

data/ 폴더의 검증용 파일을 적어 둬요. Java로 옮긴 프로그램과 원본의 출력을 같은 입력으로 비교할 때 써요.
칸의 뜻은 위 4절과 같아요.

 - data/orders.csv
   손으로 만든 주문 32줄이에요. 영업일 2006-04-03으로 돌려요.
   판매, 반품, 취소, 밤늦은 주문, TEST 메모를 섞었고, 지난 장애와 이슈에 나온 모양의 줄도 넣었어요.
   예) 1001,2006-04-03 09:12,ST01,CARD,A-100,2,6170,OK,
       본점에서 4월 3일 9시 12분에 상품 A-100을 2개, 개당 6,170원에 카드로 판 주문이에요. 메모는 없어요.

 - data/products.csv
   상품 9개예요.
   예) C-310,녹차 50T,4
       상품 C-310(녹차 50T)의 전날 마감 재고가 4개라는 뜻이에요.

 - data/many/orders.csv
   make_big.py로 만든 주문 2000줄이에요. 영업일 2006-04-03으로 돌려요.
   python3 make_big.py --orders 2000 --products 50 --seed 7 --dir data/many
   같은 명령을 다시 돌리면 같은 파일이 나와요.
   예) 100001,2006-04-03 17:40,ST02,CARD,P00046,1,26350,OK,
       신촌점에서 상품 P00046을 1개, 26,350원에 카드로 판 주문이에요.

 - data/many/products.csv
   make_big.py가 같이 만든 가상 상품 50개예요.
   예) P00001,가상 상품 1,101
       상품 P00001의 전날 마감 재고가 101개라는 뜻이에요.
