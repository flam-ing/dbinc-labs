2014.06.20
※ 교육용 가상 자료입니다.

1. 실행
 - 매일 06:00 자동. 종료 코드가 0이 아니면 스케줄러가 정산팀에 메일 보냄
 - 에러 문구도 화면(표준 출력)에 찍힘. 로그 파일 따로 없음
 - 종료 코드: 1 인자 부족 / 2 파일 없음 / 9 그 밖에

2. 위키에서 틀린 것
 - 마감 시각: 위키엔 22시라고 돼 있는데 2008년에 택배사 마감이 바뀌어서 23시로 고쳤음.
   위키는 못 고쳤음. 코드가 맞음
 - 매장표 ST05는 2013년 폐점

3. 수수료 반올림 (중요!!)
 - 회계팀이 카드사 정산 파일이랑 맞추려면 "은행가 반올림"(딱 .5면 짝수 쪽으로)을 써야 한다고 함
 - C# Math.Round 기본값이 그 방식이라 그대로 씀
   예) 1308.5 → 1308 / 1309.5 → 1310
 - 보통 반올림(.5면 무조건 올림)으로 바꾸면 카드사 파일이랑 1원씩 안 맞음. 바꾸지 말 것

4. 카드 수수료율
 - 2014.03 재계약으로 2.2%가 됐는데 코드는 아직 0.025 (2.5%)
 - 정산팀이 차액을 엑셀로 보정하고 있음
 - 고칠 때는 정산팀이랑 "며칠 자부터" 정하고 고칠 것.
   지난 날짜를 다시 돌리면 2.5%가 나와야 함

5. DBA (김 과장님)
 - 아침에 출력 맨 아래 INSERT 문을 복사해서 DB 도구로 돌림
 - SQL 모양(열 순서, 따옴표, 세미콜론, 숫자에 쉼표 없음) 바꾸면 김 과장님 쪽이 깨짐

6. 그 밖에 알아 둘 것
 - 재고 5개 기준은 2008년에 물류팀장님이 정함. 품목마다 다르게 하자는 요청 있었음(보류)
 - TEST 메모: 직원들이 test, Test, TEST 섞어 써서 대문자로 바꿔서 찾음
 - 합계가 천만 원을 넘으면 정산표에서 CARD랑 CASH 숫자가 붙어 나옴.
   정산팀은 SQL 숫자로 확인하니 그냥 둠
 - 상품표에 없는 상품(Z-999 같은 것)은 매출엔 들어가고 재고 계산엔 안 들어감
 - 반품(RTN)은 결제 수단 칸(CARD/CASH/POINT)에 안 들어가고 RETURN 칸에만 들어감
 - 구POS 날짜 슬래시 건은 장애메모 참고

7. 소스
 - 공유폴더 개발\settle\DailySettle.cs (예전 소스 관리 도구에서 옮김)
 - 빌드는 Visual Studio 2005, .NET Framework 2.0
 - 서버 교체 때 .NET Framework 2.0을 못 깐다는 얘기가 있음 → 언젠가 다른 언어로 옮겨야 할 듯
