# 회의실 예약 배치 기획서

| 공간 | 작성자 | 처음 작성 | 마지막 수정 |
| --- | --- | --- | --- |
| 전산팀 › 사내 시스템 › 회의실 | 정태윤 | 2010-01-18 | 2013-05-27(김도현) |

※ 교육용 가상 자료예요. 회사, 사람, 규정은 모두 지어낸 것이에요.

2010년 1월에 쓴 기획서예요. 프로그램은 2010년 2월 8일부터 돌았어요. 맨 아래 8절은 2013년에 김도현이 덧붙였어요.

## 1. 왜 만드나요

지금은 총무팀이 회의실 예약을 엑셀 한 장으로 받아요. 직원이 메신저로 요청하면 총무팀 담당자가 손으로 적어요. 겹치는 예약이 자주 생기고, 담당자가 자리에 없으면 예약을 할 수 없어요.

그래서 메신저 봇이 요청을 받아 파일에 쌓고, 배치가 총무팀 규정대로 검사해서 예약을 확정하게 해요. 검사 규칙은 총무팀 공간의 "회의실 예약 규정"(2009-11)을 따라요.

## 2. 쓰는 사람

| 누구 | 하는 일 |
| --- | --- |
| 직원 | 메신저 봇에게 예약, 취소, 변경, 조회를 요청해요 |
| 총무팀 | 아침에 예약표를 보고 회의실 앞에 안내문을 붙여요. 대표 사번(10001)으로 모든 예약을 취소하거나 바꿀 수 있어요 |
| 전산팀 | 배치를 돌리고, 실패한 요청과 오류를 봐요 |

## 3. 주요 기능

### 명령 네 가지

| 명령 | 하는 일 |
| --- | --- |
| RSV | 회의실을 예약해요 |
| CXL | 예약번호로 예약을 취소해요 |
| CHG | 예약번호로 날짜와 시각을 바꿔요. 회의실은 바꿀 수 없어요. 다른 방이 필요하면 취소하고 새로 예약해요 |
| QRY | 그날의 예약을 보여 줘요 |

### 예약할 때 보는 것

1. 있는 회의실인지 봐요(R01부터 R06까지, 규정 1절).
2. 날짜가 달력에 있는 날인지 봐요.
3. 30분 단위인지 봐요. 시작과 끝이 정시나 30분이어야 해요.
4. 운영 시간 안인지 봐요. 모든 회의실이 9시부터 18시까지예요.
5. 한 번에 2시간까지예요. 임원(사번 첫 자리가 9)은 시간 제한이 없어요.
6. 이미 지난 시각은 안 돼요. 요청 시각과 비교해요.
7. 오늘부터 2주 뒤까지만 받아요.
8. 인원이 회의실 정원을 넘으면 안 돼요.
9. 대회의실(R01)은 12시 30분부터 13시 30분까지 청소 시간이라 막아요.
10. 같은 회의실에 시간이 겹치는 예약이 있으면 안 돼요.

변경(CHG)도 바뀐 날짜와 시각으로 같은 검사를 해요. 취소와 변경은 예약한 본인과 총무팀(10001)만 할 수 있어요.

### 예약번호

예약이 되면 R0001부터 차례로 번호를 매겨요. 취소와 변경은 이 번호로 해요.

### 예약 확인 문자

예약이 되면 예약한 사람에게 사내 문자 서버로 확인 문자를 보내요.

## 4. 입력: 요청 파일

메신저 봇이 그날 들어온 요청을 `D:\room\req\today.txt`에 한 줄씩 쌓아요.

- 한 줄에 요청 하나예요. 칸은 쉼표로 나눠요.
- `#`으로 시작하는 줄은 메모라서 건너뛰어요. 빈 줄도 건너뛰어요.
- 요청시각은 `yyyyMMddHHmm`, 날짜는 `yyyyMMdd`, 시각은 `HHmm` 네 자리예요.

| 명령 | 칸 순서 |
| --- | --- |
| RSV | 명령, 요청시각, 사번, 이름, 회의실, 날짜, 시작, 종료, 인원, 제목 |
| CXL | 명령, 요청시각, 사번, 예약번호 |
| CHG | 명령, 요청시각, 사번, 예약번호, 날짜, 시작, 종료 |
| QRY | 명령, 요청시각, 날짜 |

예) `RSV,201002081000,10234,김민준,R02,20100210,1400,1500,6,주간 회의`
2010년 2월 8일 10시에 사번 10234 김민준이 중회의실A(R02)를 2월 10일 14시부터 15시까지, 6명, "주간 회의"로 예약해 달라는 요청이에요.

봇은 이번에 고쳐서 회의실을 번호로, 시각을 네 자리로 보내요. 2009년판 봇은 회의실을 이름(대회의실 같은 것)으로 보내기 때문에, 배치가 이름도 번호로 바꿔서 받아요.

## 5. 출력

- 처리 결과: 요청 줄마다 한 줄씩 찍어요. `[줄번호] 명령 OK 내용` 또는 `[줄번호] 명령 ERR 실패 이유` 모양이에요.
- 예약표: 처리가 끝나면 날짜별로 예약을 찍어요. 회의실, 시각, 예약번호, 이름, 인원, 제목 순서예요.
- 마지막 줄에 성공 건수와 실패 건수를 찍어요.
- 화면 출력을 총무팀 공유 폴더에 `room_yyyyMMdd.txt`로 저장해요.
- 확정된 예약은 그룹웨어 DB(`TB_ROOM_RSV`)에 저장해요. 다음 날 배치는 DB에 있는 예약과 겹치는지 봐요.

## 6. 운영

- 배치 서버의 작업 스케줄러가 매일 밤 11시에 돌려요.
- 명령: `java -cp classes;lib/ojdbc14.jar com.nuri.room.RoomBatch D:\room\req\today.txt`
- DB 접속 정보는 `conf/db.properties`에 둬요.
- 요청 파일을 열 수 없으면 종료 코드 2, 인자가 없으면 1로 끝나요.
- 개발 환경: JDK 6

## 7. 하지 않는 것

- 매주 같은 시간 반복 예약은 받지 않아요. 매번 따로 예약해요.
- 총무팀이 하루를 통째로 잡아 두는 가예약(HLD)은 1차에 넣지 않아요. 총무팀과 다시 이야기해요.
- 대기 예약이나 빈 방 추천은 하지 않아요.
- 회의실 정보(이름, 정원, 층)를 고치는 화면은 없어요. 1차는 소스에 두고, 나중에 그룹웨어 DB로 옮겨요.
- 누가 언제 예약을 바꿨는지 이력은 1차에 남기지 않아요.
- 다과, 비품 신청은 받지 않아요. 그룹웨어 총무 신청 메뉴를 써요.

## 8. 시험용 요청 파일 (data 폴더) — 2013-05-27 김도현 덧붙임

담당을 넘겨받으면서 적어요. 위 1~7절은 2010년 1월 기획 그대로예요. 그 뒤에 바뀐 것은 운영 메모, 규정 페이지와 댓글, 시설관리 페이지, 이슈를 같이 봐요.

동작을 확인할 때 쓰는 요청 파일이에요. 칸 순서는 4절과 같아요. DB 없이 이렇게 돌려요.

    java -cp classes com.nuri.room.RoomBatch data/commands.txt

| 파일 | 무엇 |
| --- | --- |
| `commands.txt` | 2010-03-12부터 15일까지 봇이 모은 요청 38줄이에요. 예약, 취소, 변경, 조회와 형식이 틀린 줄이 섞여 있어요 |
| `month.txt` | 2010년 4월 한 달 치 요청 325줄이에요. 봇 로그에서 뽑았어요. 양이 많을 때 확인해요 |
| `old-bot.txt` | 총무팀 PC의 2009년판 봇이 보낸 요청 7줄이에요. 회의실은 이름으로, 시각은 앞의 0 없이 와요 |
| `empty.txt` | 요청이 없는 날(토요일)의 파일이에요. 메모 한 줄뿐이에요 |

`commands.txt` 예) `RSV,201003120910,10234,김민준,R01,20100315,0900,1030,8,주간 업무 회의`
2010년 3월 12일 9시 10분에 사번 10234 김민준이 대회의실(R01)을 3월 15일 9시부터 10시 30분까지, 8명, "주간 업무 회의"로 예약해 달라는 요청이에요.

`commands.txt`의 취소 예) `CXL,201003121300,10234,R0002`
사번 10234가 예약번호 R0002를 취소해 달라는 요청이에요.

`month.txt` 예) `RSV,201003161139,20041,황보람,중회의실B,20100401,1500,1630,7,파트 회의`
계약직 사번 20041 황보람이 중회의실B를 4월 1일 15시부터 16시 30분까지 7명으로 예약해 달라는 요청이에요. 회의실이 이름으로 왔어요.

`old-bot.txt` 예) `RSV,201003121000,10234,김민준,대회의실,20100317,900,1030,8,주간 회의`
옛 봇이 보낸 요청이에요. 회의실이 `R01`이 아니라 `대회의실`이고, 시작 시각이 `0900`이 아니라 `900`이에요.

`empty.txt` 예) `# 2010-03-20 (토) 들어온 요청 없음`
메모 줄이라 처리할 요청이 없어요. 예약표에 "예약 없음"이 나와요.
