# 회의실 예약 배치 운영 메모

| 공간 | 작성자 | 처음 작성 | 마지막 수정 |
| --- | --- | --- | --- |
| 전산팀 › 사내 시스템 › 회의실 | 정태윤 | 2010-07-20 | 2011-03-15 |

※ 교육용 가상 자료예요. 회사, 사람, 서버는 모두 지어낸 것이에요.

## 1. 어떻게 돌아가나요

1. 직원이 메신저 봇에게 회의실을 예약하거나 취소하라고 말해요.
2. 봇은 요청을 한 줄씩 그달의 요청 파일에 쌓아요(`D:\room\req\yyyyMM.txt`).
3. 배치 서버의 작업 스케줄러가 매일 밤 11시에 RoomBatch를 실행해요. RoomBatch는 그달 파일을 처음 줄부터 다시 처리해서 예약표를 새로 만들어요.
4. 표준 출력이 총무팀 공유 폴더에 `room_yyyyMMdd.txt`로 저장돼요. 총무팀은 아침에 이 파일을 보고 회의실 앞 안내문을 붙여요.

예약 내용을 따로 저장하지 않아요. 날마다 그달 파일 전체를 처음부터 다시 처리해서 예약표를 만들어요. 그래서 예약번호(R0001 같은 번호)는 매일 같은 순서로 다시 매겨져요.

## 2. 왜 DB가 아니라 파일인가요

처음(2010년 2월)에는 그룹웨어 DB에 예약을 저장했어요. 2010년 7월 보안 점검 뒤에 그룹웨어 DB 계정이 막혔고, 다시 열어 달라는 요청은 아직 처리되지 않았어요. 그래서 7월 19일부터 임시로 파일 방식으로 바꿨어요. 코드에 주석으로 남은 DB 코드가 그때 것이에요.

## 3. 한 달 파일이 너무 커지면

배치는 예약을 최대 500건까지만 들고 있을 수 있어요. 2010년 12월 말에 예약이 500건을 넘자, 그 뒤 예약이 모두 "형식 오류"로 떨어졌어요. 그래서 요청 파일을 달마다 새로 시작하게 봇 설정을 바꿨어요.

## 4. main 첫 줄의 시간대 고정 (2011-03-14 장애)

2011년 3월 초에 배치 서버를 새 장비로 바꿨어요. 새 장비의 시간대가 미국 서부로 잡혀 있었는데, 미국 서머타임이 시작된 주에 날짜 차이 계산이 하루 모자라게 나왔어요. 그래서 15일 뒤 예약이 "2주 이내"로 통과했어요. 3월 14일에 main 첫 줄에서 시간대를 서울로 고정했어요. 서버 시간대를 바꾸는 것은 인프라팀이 안 된다고 했어요. 이 줄은 지우지 마세요.

## 5. 옛 메신저 봇

총무팀 PC 한 대에 2009년판 봇이 아직 남아 있어요. 옛 봇은 회의실을 번호 대신 이름으로 보내고, 시각 앞의 0을 빼고 보내요(0900을 900으로). 이름은 프로그램이 번호로 바꿔 주지만, 시각은 그대로 들어와서 문제가 생겨요(ROOM-23).

## 6. 봇 안내문에 넣은 것

- 제목에 쉼표를 쓰지 마세요. 쉼표 뒤는 잘려요.
- 제목을 비우면 예약이 되지 않아요.
- 인원은 숫자로 적어 주세요.

## 7. 끈 기능

예약 확인 문자는 2010년 12월에 문자 서버 계약이 끝나서 껐어요. 코드는 남아 있지만 부르지 않아요.
