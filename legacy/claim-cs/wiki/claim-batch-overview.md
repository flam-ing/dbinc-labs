# 자동 심사 배치(ClaimReview) 운영 안내

| 공간 | 작성자 | 마지막 수정 |
| --- | --- | --- |
| 보상시스템 (CLAIM) | 정민호 | 2013-06-24, 정민호 |

※ 교육용 가상 자료예요. 회사, 상품, 사람, 금액, 규정은 모두 지어낸 것이에요.

## 무엇을 하나요

매일 아침 전날 접수된 보험금 청구를 상품 규칙에 따라 자동으로 심사해요. 결과는 네 가지예요.

| 결과 | 뜻 | 다음 일 |
| --- | --- | --- |
| AUTO | 자동 승인 | 오후 지급 파일에 들어가요 |
| PART | 부분 지급 | 한도나 감액 규칙만큼만 지급해요 |
| REJECT | 거절 | 고객에게 거절 안내 문자가 나가요 |
| MANUAL | 사람 심사 | 보상팀 심사 담당자가 화면에서 직접 봐요 |

## 하루 흐름

| 시각 | 일 |
| --- | --- |
| 06:50 | 계약 시스템이 전날 접수된 청구 파일(`claim_yyyyMMdd.csv`)을 `D:\CLAIM\IN`에 내려놓아요 |
| 07:30 | 작업 스케줄러(CLAIM_REVIEW)가 배치를 돌려요 |
| 08:00 | 심사 화면이 배치 결과를 올려요 |
| 14:00 | AUTO와 PART 건이 지급 파일로 나가요 |

상품표(`product.csv`)는 상품팀이 매달 1일에 새로 줘요.

## 입력 파일

청구 파일의 열이에요. 열 순서는 계약 시스템이 정해요.

| 열 | 뜻 | 비고 |
| --- | --- | --- |
| CLM_NO | 청구 번호 | |
| POL_NO | 증권 번호 | |
| PRD_CD | 상품 코드 | 상품표의 PRD_CD |
| DX_CD | 진단 코드 | 질병 분류 코드 앞 3자리예요. S, T로 시작하면 상해예요 |
| HOSP_DAYS | 입원 일수 | 통원이면 0 |
| CLM_AMT | 청구 금액 | 병원비 영수증 합계 |
| JOIN_DT | 가입일 | 계약 시스템 값이라 언제나 yyyyMMdd예요 |
| ACC_DT | 사고일(진단일) | 접수 담당자가 입력해요. 아래 설명을 봐요 |
| PREV_CNT | 지난 1년 청구 횟수 | 계약 시스템이 세어 줘요 |
| RCV_CH | 접수 채널 | BR 지점, CC 콜센터, ML 우편 |

사고일은 접수 채널마다 모양이 달라요. 지점과 콜센터 화면은 `2013-02-11`처럼 저장해요. 우편 접수는 아직 VB6 접수 화면으로 입력해서 `02/11/2013`(월/일/년)처럼 저장해요.

상품표에는 상품 코드, 유형(SL 실손, HS 입원 일당, DG 진단), 한도, 지급률, 자기부담금, 일당, 면책 일수(WAIT_DAYS), 판매 여부(SALE_YN)가 있어요. 면책 기간은 상품표의 WAIT_DAYS를 따라요.

## 출력

2013-06부터 배치는 결과를 파일로 쓰지 않고 화면(표준 출력)에만 써요. 작업 스케줄러가 그 출력을 `result_yyyyMMdd.txt`로 받아 두고, 심사 화면이 이 파일을 올려요.

심사 화면은 글자 위치로 칸을 잘라서 읽어요. 그래서 열 너비, 열 순서, 금액의 쉼표, 맨 아래 합계 표를 바꾸면 업로드가 깨져요. 출력 모양을 바꿔야 하면 심사 화면 담당자와 먼저 이야기해요.

## 사유 코드

| 코드 | 뜻 |
| --- | --- |
| 00 | 정상 |
| 11 | 한도 초과(부분 지급) |
| 21 | 면책 기간 |
| 22 | 암 면책(1년) |
| 23 | 입원 3일 이하 |
| 24 | 청구 기한(3년) 지남 |
| 31 | 상품 없음 |
| 32 | 단종 상품 |
| 41 | 중복 청구 |
| 51 | 고액(지급 예정 300만 원 이상, 재보험) |
| 90 | 자료 오류 |

## 장애가 나면

배치가 0이 아닌 종료 코드로 끝나면 스케줄러가 보상시스템 담당자에게 문자를 보내요. 따로 남는 로그 파일은 없어요. 스케줄러가 받아 둔 출력 파일을 봐요.

| 종료 코드 | 뜻 |
| --- | --- |
| 1 | 인자가 모자라거나 기준일 모양이 틀림 |
| 2 | 입력 파일이 없음 |
| 9 | 그 밖의 오류(출력 맨 끝에 ERROR 줄) |

## 검증용 자료

2013-03 운영 자료에서 개인 정보를 지우고 만든 검증용 파일이 있어요(`claims.csv`, `products.csv`, 기준일 20130304). 코드를 고치면 이 자료로 돌려서 고치기 전 결과와 비교해요.
