# 자동 심사 배치 기획서 (VB6 일괄 심사를 C# 배치로)

| 공간 | 작성자 | 마지막 수정 |
| --- | --- | --- |
| 보상시스템 (CLAIM) | 정민호 | 2013-03-11, 정민호 |

※ 교육용 가상 자료예요. 회사, 상품, 사람, 금액, 규정은 모두 지어낸 것이에요.

2012-02-13에 쓴 기획서예요. 개발은 2012-03에 끝났어요. 맨 아래 두 덧붙임(상품 마스터, 검증용 자료)은 나중에 붙였어요.

## 왜 만드나요

- 2004년에 외주로 만든 VB6 심사 프로그램에는 심사 화면과 "일괄 심사" 단추가 같이 있어요. 지금은 보상팀 담당자가 아침마다 이 단추를 눌러서 전날 접수분을 심사해요. 담당자가 자리에 없으면 심사가 밀려요.
- 일괄 심사 부분만 C# 배치로 옮겨서 작업 스케줄러가 매일 아침 돌리게 해요. 심사 화면은 VB6를 그대로 써요.
- 옮기는 동안 심사 결과는 VB6와 같아야 해요. 규칙을 바꾸는 일은 옮긴 뒤에 따로 해요.

## 쓰는 사람

| 누구 | 하는 일 |
| --- | --- |
| 보상팀 심사 담당 | 아침에 심사 화면에서 배치 결과를 올리고, MANUAL 건을 직접 심사해요 |
| 보상팀장 | 하루 합계(결과별 건수와 지급액)를 봐요 |
| 상품팀 | 상품 마스터(한도, 지급률, 면책 기간)를 관리해요 |
| 보상시스템 담당 | 배치를 운영하고, 오류 문자를 받아요 |

## 주요 기능: 심사 순서

청구 한 건마다 아래 순서로 봐요. 먼저 걸린 규칙에서 결과가 정해져요. 결과는 AUTO(자동 승인), PART(부분 지급), REJECT(거절), MANUAL(사람 심사) 넷 가운데 하나예요. REJECT와 MANUAL은 지급액을 0원으로 적어요.

1. 상품 찾기: 상품 마스터에 없는 상품 코드면 REJECT 31이에요.
2. 단종 상품: 판매 여부(SALE_YN)가 N이면 MANUAL 32예요. 옛 약관을 따라야 해서 사람이 봐요.
3. 중복 청구: 같은 날 파일 안에 증권 번호, 사고일, 진단 코드가 모두 같은 청구가 또 있으면 두 번째부터 REJECT 41이에요.
4. 청구 기한: 사고일부터 기준일까지 3년(1,095일)이 넘으면 REJECT 24예요(약관).
5. 상품 유형별 규칙: 아래 세 표를 따라요.
6. 고액: 지급 예정액이 300만 원 이상이면 MANUAL 51이에요. 재보험사에 지급 전에 알려야 하는 건이라 사람이 봐요.

### 실손(SL)

- 질병(진단 코드가 S, T로 시작하지 않음): 가입일부터 사고일까지 날수가 면책 기간보다 짧으면 REJECT 21이에요. 면책 기간은 상품 마스터의 WAIT_DAYS를 써요. 약관이 바뀌어도 상품팀이 마스터만 고치면 돼요.
- 상해(S, T로 시작): 면책 기간이 없어요. 다만 가입하고 30일 안에 난 사고는 MANUAL 53이에요(2011-10 보험사기 대응 TF 결정).
- 지급액: 청구 금액에서 자기부담금(SELF_AMT)을 빼고 지급률(PAY_RATE)을 곱해요. 10원 미만은 버려요(약관).
- 지급액이 0원 이하면 REJECT 25예요. 한도(LIMIT_AMT)를 넘으면 한도까지만 주고 PART 11이에요. 그 밖에는 AUTO 00이에요.

### 입원 일당(HS)

- 면책 기간과 상해 30일 기준은 실손과 같아요.
- 입원 3일까지는 주지 않아요(REJECT 23). 4일째부터 하루에 일당(DAY_AMT)을 줘요.
- 일당 상품은 LIMIT_AMT 칸에 지급 일수 한도를 적어요. 지급 일수가 한도를 넘으면 한도 일수까지만 주고 PART 11이에요.

### 진단(DG)

- 암(C로 시작)과 제자리암(D00부터 D09까지)만 보장해요. 그 밖의 진단은 REJECT 26이에요.
- 가입일부터 1년이 지난 날부터 보장해요. 그 전에 진단되면 REJECT 22예요.
- 지급액은 가입금액(LIMIT_AMT)에 진단 묶음 지급률을 곱해요. 갑상선암(C73) 20%, 제자리암 10%, 그 밖의 암 100%예요. 10원 미만은 버려요.
- 지급률이 100%가 아니면 PART 12, 100%면 AUTO 00이에요.

## 입력

### 청구 파일

계약 시스템이 매일 06:50에 전날 접수된 청구를 `D:\CLAIM\IN\claim_yyyyMMdd.csv`로 내려놓아요. 첫 줄은 제목이에요. 칸이 10개보다 적은 줄은 심사하지 않고 건너뛰어요(VB6와 같아요).

| 칸 | 뜻 | 모양 |
| --- | --- | --- |
| CLM_NO | 청구 번호 | |
| POL_NO | 증권 번호 | |
| PRD_CD | 상품 코드 | 상품 마스터의 PRD_CD |
| DX_CD | 진단 코드 | 질병 분류 코드 앞 3자리. S, T로 시작하면 상해 |
| HOSP_DAYS | 입원 일수 | 통원이면 0 |
| CLM_AMT | 청구 금액 | 원, 숫자만 |
| JOIN_DT | 가입일 | yyyyMMdd |
| ACC_DT | 사고일(진단일) | 지점, 콜센터는 yyyy-MM-dd. 우편은 VB6 접수 화면이라 MM/dd/yyyy |
| PREV_CNT | 지난 1년 청구 횟수 | 계약 시스템이 세어 줘요 |
| RCV_CH | 접수 채널 | BR 지점, CC 콜센터, ML 우편 |

예) `C1202001,P0900031,SL02,J20,0,85000,20090502,2012-02-10,1,BR`
청구 C1202001은 증권 P0900031의 실손 알뜰형(SL02) 청구예요. 진단 J20, 통원, 청구 금액 85,000원, 2009-05-02 가입, 2012-02-10 사고, 지난 1년 청구 1번, 지점 접수예요.

### 상품 마스터

상품 DB의 `TB_PRODUCT`에서 판매 중이거나 보장이 남은 상품(USE_YN이 Y)을 읽어요. 상품팀이 매달 1일에 고쳐요.

| 칸 | 뜻 |
| --- | --- |
| PRD_CD | 상품 코드 |
| PRD_NM | 상품 이름 |
| PRD_TYPE | 유형. SL 실손, HS 입원 일당, DG 진단 |
| LIMIT_AMT | 한도. 실손은 금액, 일당은 일수, 진단은 가입금액 |
| PAY_RATE | 지급률(실손) |
| SELF_AMT | 자기부담금(실손) |
| DAY_AMT | 하루 일당(일당 상품) |
| WAIT_DAYS | 질병 면책 일수 |
| SALE_YN | 판매 여부. N이면 단종 |

### 기준일

실행할 때 `yyyyMMdd`로 받아요. 보통 배치를 돌리는 날이에요. 청구 기한(3년)을 이 날짜로 재요.

## 출력

- 결과 파일: `D:\CLAIM\OUT\result_yyyyMMdd.csv`에 청구마다 한 줄씩 결과, 사유 코드, 지급액을 써요. 08:00에 심사 화면이 이 파일을 올려요.
- 화면(표준 출력): 같은 내용을 표로 찍고(청구 번호, 상품, 진단, 청구 금액, 지급액, 결과, 사유), 맨 아래에 결과별 건수와 지급액 합계를 찍어요. 보상팀장이 이 합계를 봐요.

## 운영

- 작업 스케줄러 `CLAIM_REVIEW`가 매일 07:30에 돌려요.
- 명령: `ClaimReview.exe <청구 CSV> <기준일 yyyyMMdd>`
- 종료 코드: 0 정상, 1 인자가 모자라거나 기준일 모양이 틀림, 2 입력 파일 없음, 9 그 밖의 오류. 0이 아니면 스케줄러가 보상시스템 담당자에게 문자를 보내요.
- AUTO와 PART 건은 14:00 지급 파일에 들어가요. 지급 파일은 지급 시스템이 만들어요.
- 개발 환경: Visual Studio 2010, .NET Framework 4.0

## 하지 않는 것

- 심사 화면은 옮기지 않아요. VB6 화면을 그대로 써요.
- 지급 파일과 고객 안내 문자는 만들지 않아요. 지급 시스템과 문자 시스템이 배치 결과를 읽어서 해요.
- 연령 할증은 2012-03 약관에서 없어져서 옮기지 않아요.
- 해지 계약은 계약 시스템이 청구 파일을 만들 때 빼요. 배치는 해지 여부를 보지 않아요.
- 접수 채널(RCV_CH)과 지난 1년 청구 횟수(PREV_CNT)는 파일에 있지만 1차 심사에는 쓰지 않아요. 보상팀이 기준을 정하면 넣어요.
- 지난 날짜 파일과의 중복은 보지 않아요. 같은 날 파일 안에서만 봐요.

### 덧붙임 (2013-03-11, 정민호): 검증용 자료 (data 폴더)

위 본문은 2012년 기획 그대로예요. 그 뒤에 바뀐 규칙은 심사 기준, 운영 안내, 이슈를 같이 봐요.

코드를 고친 뒤에 고치기 전과 결과를 비교하려고 검증용 자료를 만들었어요. 2013-03 운영 자료에서 개인 정보를 지우고 만들었어요. 기준일 `20130304`로 돌려요.

| 파일 | 무엇 |
| --- | --- |
| `claims.csv` | 청구 39건이에요. 그동안 문제가 됐던 모양의 줄도 몇 개 남겼어요 |
| `claims_empty.csv` | 제목 줄만 있는 청구 파일이에요. 접수가 없는 날(연휴 다음 날 같은 때) 계약 시스템이 이런 파일을 내려 줘요 |
| `products.csv` | 상품 마스터를 엑셀로 내린 파일이에요. 상품 5개예요 |

`claims.csv` 예) `C1303001,P1000101,SL01,J20,0,452000,20090315,2013-02-11,0,BR`
청구 C1303001은 증권 P1000101의 실손 기본형(SL01) 청구예요. 진단 J20, 통원(입원 0일), 청구 금액 452,000원, 2009-03-15 가입, 2013-02-11 사고, 지난 1년 청구 0번, 지점(BR) 접수예요.

`claims_empty.csv` 예) `CLM_NO,POL_NO,PRD_CD,DX_CD,HOSP_DAYS,CLM_AMT,JOIN_DT,ACC_DT,PREV_CNT,RCV_CH`
이 제목 줄 한 줄뿐이에요. 청구가 없으면 표는 비고 합계는 모두 0이어야 해요.

`products.csv` 예) `SL01,누리실손 기본형,SL,3000000,0.9,10000,0,90,Y`
상품 SL01은 실손이고 한도 300만 원, 지급률 90%, 자기부담금 1만 원, 일당 없음, 면책 90일, 판매 중이에요.
일당 상품은 한도 칸이 일수예요. `HS01,누리 입원일당,HS,120,0,0,30000,90,Y`는 한도 120일, 하루 3만 원이에요.
