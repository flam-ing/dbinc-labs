# 동네카페 포인트: 구조 설명

## 무슨 프로그램인가
카페가 매일 마감할 때 `python3 cafe.py`를 한 번 돌리는 포인트 적립 프로그램이에요. 그날 주문(`data/orders.csv`)을 회원 명부(`data/members.csv`)에 반영해서 영수증을 출력하고, 갱신된 명부와 마감 보고서를 `out/`에 저장해요.

## 파일별 역할

| 파일 | 역할 |
| --- | --- |
| `cafe.py` | 핵심 프로그램. 주문 처리, 영수증 출력, 저장, 보고서 작성을 전부 한 파일에서 해요. 모듈 맨 아래의 `run()`이 import 즉시 실행돼요. |

| `data/members.csv` | 입력. 회원 4명(id, 이름, 생일, 누적 결제, 포인트, 등급) |

## 주문 한 줄이 저장되기까지

1. **시작**: 파일을 실행하면 맨 아래 `run()`이 호출돼요.
2. **명부 읽기**: `hoewon_bulleogi()`가 `members.csv`를 `{id: 행}` 딕셔너리로 메모리에 올려요.
3. **주문 읽기**: `orders.csv`를 한 줄씩 돌면서 건수를 세요.
4. **비회원 분기**: 회원id가 비어 있으면 금액을 그대로 매출에 더하고 영수증만 찍어요. 포인트와 명부는 건드리지 않고 다음 줄로 넘어가요.
5. **포인트 사용 정리**: 회원이면 `use_points`를 보정해요. 보유 포인트보다 많으면 보유량으로 줄이고, 1,000점 미만이면 0으로 만들어요.
6. **생일 쿠폰 판단**: 주문 월이 생일 월과 같고, 그 달 쿠폰을 아직 안 썼고, 금액이 5,000원 이상이면 생일 분기로 들어가요. 아니면 일반 분기로 가요.
7. **결제 금액과 적립 계산**:
   - 생일 분기: `결제 = 금액 - 3000 - 사용포인트`. 적립은 **주문 금액**의 1%(VIP는 3%)예요.
   - 일반 분기: `결제 = 금액 - 사용포인트`. 적립은 **결제 금액**의 1%(VIP는 3%)예요.
   - 두 분기 모두 12/25면 적립이 2배가 돼요. 지금 날짜들은 2026년이라 걸리지 않아요.
8. **메모리 명부 갱신**: 포인트는 `기존 - 사용 + 적립`, 누적 결제는 `기존 + 결제 금액`으로 바꿔요. 누적이 10만 원 이상이면 등급을 VIP로 올려요. 같은 사람의 다음 주문은 이미 갱신된 값을 보고 처리해요.
9. **영수증 출력**: 화면에 주문 금액, 쿠폰, 포인트 사용, 결제 금액, 적립, 남은 포인트를 찍어요. 일반 등급이면 VIP까지 남은 금액도 보여 줘요.
10. **저장**: 주문을 다 돌면 `saveMembers()`가 `out/members.csv`를 써요. `try/except: pass`로 감싸 있어서 저장에 실패해도 조용히 넘어가요.
11. **보고서**: `time.sleep(1)` 뒤에 VIP 인원을 세서 `out/report.txt`에 주문 수, 매출, 적립 합계, VIP 수, 적립률 문구를 써요.

## 눈에 띄는 점 (고치지는 않았어요)
- **같은 일을 하는 코드가 여러 군데 있어요.** 회원 읽기 함수가 두 개(`hoewon_bulleogi`, `load_members`)이고, 생일 분기와 일반 분기도 거의 복사본이에요. 적립률이 `cafe.py`(생일·일반 2곳), `points.js`, 영수증 문구, 보고서 문구, README에 흩어져 있어서 CAFE-1을 하려면 전부 따로 찾아 바꿔야 해요.
- **규칙이 어긋나요.** 생일 분기는 쿠폰을 뺀 금액이 아니라 주문 금액으로 적립해서, 일반 분기와 기준이 달라요. README는 "결제 금액의 1%"라고 쓰여 있어요. 또 이번 데이터에서 M003은 보유 800점인데 사용 요청이 0이라 문제가 없지만, M004의 사용 500점은 1,000점 미만이라 0으로 처리돼요.
- **죽은 코드와 위험 요소**가 있어요: `run2`, 주석 처리된 옛 코드, `reset_points`, 관리자 비밀번호가 소스(`cafe.py`, `App.tsx`)에 평문으로 들어 있어요. 키오스크에서는 검색창에 비밀번호를 치면 관리자 버튼이 나와요.
- `run()`이 파일 맨 아래에서 바로 실행돼서 import만 해도 마감이 돌아가요. 전역 변수 `maechul`도 있어서 테스트하기 어려운 구조예요.

나머지 이슈(CAFE-2~5)와 실제 실행 결과는 아직 보지 않았어요. 원하시면 이어서 읽거나 돌려 볼게요.
