## A. 결과가 달라지지 않는 리팩터링 (이 순서로)

0. **기준선 저장**: 지금 코드로 `python3 cafe.py`를 돌려 stdout, `out/members.csv`, `out/report.txt`를 저장해 둡니다. 이후 매 단계에서 이것과 diff를 떠서 결과가 같은지 확인하려는 것입니다. `reset_points`는 실행하지 않습니다.
1. **죽은 코드 제거**: `run2()`, 미사용 `load_members()`, 주석 처리된 2019년 코드를 지우고 `hoewon_bulleogi()`는 로더 하나로 정리합니다. 가장 안전하고 뒤 단계에서 읽을 양이 줄어듭니다.
2. **정책 상수를 한 곳으로**: 적립률, VIP 기준, 쿠폰 금액과 조건, 크리스마스 날짜를 모읍니다. 분기를 합치기 전에 숫자부터 모아야 복제가 줄어듭니다.
3. **`run()` 분리**: 주문 읽기, 주문 1건 처리, 영수증 출력, 마감 보고, 저장으로 나눕니다. 큰 함수를 쪼개야 다음 단계에서 두 분기를 합칠 수 있습니다.
4. **두 분기 통합**: 쿠폰 유무만 인자로 두고 하나의 경로로 합칩니다. 적립 기준 금액(`amt`/`gyeolje`)은 현재 동작 그대로 남깁니다. 버그 수정(B-1)과 섞이면 diff 비교가 깨지기 때문입니다.
5. **등급을 `Grade` enum으로 통일**: 문자열 비교를 없애고, 변환은 CSV 읽기/쓰기 경계에서만 합니다. 통합된 경로 한 곳만 고치면 되고, CAFE-4(새 등급)의 선행 작업이기도 합니다.
6. **파일 처리 정리**: `with open`을 쓰고 `if __name__ == "__main__":` 가드를 넣습니다. 실행 방법은 그대로이고 import해서 테스트할 수 있게 됩니다. 구조가 정리된 뒤에 해야 충돌이 없습니다.
7. **영수증·보고 문구를 상수에서 생성**: "(일반 1%, VIP 3%)", "기준 누적 100000원" 등입니다. 상수(2)와 분기 통합(4)이 끝나야 한 곳에서 만들 수 있습니다.
8. **web/src 정리**: `grade: any`를 구체 타입으로 바꾸고, `var`/`==`를 `const`/`===`로 바꾸고, 정책 상수를 분리하고, `calcPoint`를 Python 규칙과 맞춥니다. Python 쪽 상수와 등급이 확정된 뒤에 한 번에 맞추려는 순서입니다. 다만 `web/README.md`와 CLAUDE.md는 web을 읽기 전용으로 취급하라고 하므로, 수정해도 되는지 먼저 확인이 필요합니다.

## B. 고치면 결과가 달라지는 것 (리팩터링과 분리, 항목마다 승인)

**버그**
- **B-1**: 생일 쿠폰 분기는 쿠폰 차감 전 `amt`로 적립하고, 일반 분기는 `gyeolje`로 적립합니다 (CAFE-5).
- **B-2**: 포인트 사용액(`use`)이 크면 결제 금액이 0 미만이 될 수 있습니다. 검증이 없습니다.
- **B-3**: `members.csv`에 없는 회원 ID가 있으면 `KeyError`로 마감 전체가 멈춥니다.
- **B-4**: 쿠폰 중복 방지 키가 `id+월`이라 연도가 달라도 같은 달이면 한 번만 적용됩니다.
- **B-5**: `saveMembers` 실패를 `try/except: pass`로 삼킵니다. 이걸 고치면 지금은 안 보이던 실패가 드러납니다.
- **B-6**: `HoewonCard`가 `App` 안에 정의돼 있어 입력할 때마다 새로 만들어지고, 펼침 상태가 초기화됩니다. 밖으로 빼면 동작이 바뀝니다.
- **B-7**: 적립 계산이 `int(x*0.03)` 같은 부동소수점입니다. 정수 연산으로 바꾸면 경계값에서 1점이 달라질 수 있습니다. 음수에서는 Python `int`(0 방향)와 JS `Math.floor`(내림)도 다릅니다.

**정책**
- **P-1**: 2020-12-25 포인트 두 배 분기(날짜 하드코딩)를 유지할지 지울지 정해야 합니다.
- **P-2**: 적립률, VIP 기준, 생일 쿠폰 변경과 새 등급은 CAFE-1~4의 "같이 바꿀 것"을 보고 따로 진행합니다.
- **P-3**: `time.sleep(1)`("지우지 마시오")은 이유가 확인되지 않아 요청 없이는 유지합니다.
- **P-4**: `calcPoint`의 `console.log` 제거는 브라우저 콘솔 출력이 사라지는 변화입니다.

**보안**
- **S-1**: 관리자 비밀번호 `cafe1234`가 `cafe.py`와 `App.tsx`에 평문으로 있습니다. 키오스크 번들에 노출되고, 검색창에 비밀번호를 치면 관리자 버튼이 열리는 클라이언트 검사입니다. git 기록에도 남아 있어 교체와 서버 쪽 검증이 필요합니다.
- **S-2**: `reset_points()`는 비밀번호 한 줄로 모든 포인트를 0으로 만듭니다. 삭제할지 보호할지는 사용자가 정해야 합니다.

A는 단계마다 기준선과 diff로 확인하고, B는 의도한 차이만 나오는지 따로 확인합니다.
