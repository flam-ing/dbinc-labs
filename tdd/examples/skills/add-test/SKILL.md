`$ARGUMENTS`의 단위 테스트를 우리 팀 규칙대로 써 주세요.

1. 대상 코드와 이미 있는 테스트를 먼저 읽어요. 같은 폴더의 테스트 모양을 따라요.
2. 테스트 이름은 한글로 `무엇은_어떻게_된다` 모양으로 써요.
3. 경계값 사례를 3개 이상 넣어요. 예를 들면 빈 값, 가장 짧은 값, 가장 긴 값이에요.
4. 테스트마다 `// 준비`, `// 실행`, `// 확인` 주석으로 세 부분을 나눠요(파이썬은 `#`).
5. 대상 코드가 `RULES.md`의 규칙에 걸리면 그 규칙의 표에 있는 사례도 넣어요.
6. 테스트 파일만 만들거나 고쳐요. 테스트가 아닌 파일은 절대 고치지 않아요.
7. 프로젝트의 테스트 명령을 돌려요. 서버는 `cd api && ./gradlew test`, 화면은 `cd web && npm test`, 파이썬은 `cd py && python3 -m unittest`예요.
8. 결과는 통과한 테스트 수와 실패한 테스트 이름만 짧게 알려 줘요. 실패해도 대상 코드는 고치지 않아요.
