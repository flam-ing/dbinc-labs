## Claude의 답 (고치지 않았어요)

README 기준으로, 모델 바깥에서 하네스가 더해 주는 것 세 가지입니다.

1. **여러 일꾼에게 나눠 맡기기:** `task`가 서로 격리된 작업 공간(worktree)에서 하위 에이전트를 여러 개 돌리고, 그 결과를 정해진 형식으로 검증해서 받아요. `/review`는 검토 에이전트 여러 명이 문제를 P0~P3로 등급을 매겨 줍니다.
2. **코드 편집·이해 도구:** 편집할 때 내용 해시로 위치를 가리켜서, 파일이 이미 바뀌었으면 낡은 편집은 적용하지 않고 거절해요. 파일 이름을 바꿀 때는 LSP(코드 분석 서버)가 import를 같이 고쳐 주고, 디버거(DAP)도 에이전트가 직접 조작할 수 있습니다.
3. **실수를 막는 감시 장치:** 모델의 출력이 정규식 규칙에 걸리면 도중에 끊고 규칙을 시스템 알림으로 끼워 넣어 다시 시도시켜요. 별도의 검토 모델(advisor)이 매 턴을 읽고 메모를 남기기도 합니다.

README에 개수가 구간마다 다르게 적힌 항목(포팅한 유틸리티 수 등)이 있어서, 숫자는 일부러 뺐어요.
