## Claude의 답 (고치지 않았어요)

배포 전에 확인할 항목은 다음 다섯 가지예요.

1. **UI 필터와 API 응답의 대소문자 불일치**: API는 이제 `"paid"`를 주는데 필터는 아직 `"PAID"`와 비교해요. 이대로 나가면 결제완료 필터를 골랐을 때 주문이 하나도 안 보여요. 두 변경을 함께 맞춰서 배포해야 해요. (UI-104, API-212)
2. **DB 값도 바뀌는지**: API-212가 응답만 소문자로 바꾸는지, DB에 저장되는 값까지 바꾸는지 확인해야 해요. DB 값까지 바뀌면 야간 리포트의 `status = 'PAID'` 조건에 맞는 주문이 없어서 매출이 0으로 나와요. (API-212, BATCH-07)
3. **큰 테이블 인덱스 생성 방식**: 주문 120만 건 테이블이라 인덱스를 만드는 동안 테이블이 잠기지 않는 방식(온라인 생성 등)인지, 얼마나 걸리는지 확인해야 해요. 상태 값 표기가 바뀌는 시점과 겹칠 때 인덱스가 의도대로 쓰이는지도 함께 봐야 해요. (DB-031, API-212)
4. **409 응답 처리**: 클라이언트가 409를 받았을 때 실패로 보여 주지 않고 "이미 처리된 결제"로 다루는지 확인해야 해요. 요청 키를 10분 동안 어디에 저장하는지, 서버가 여러 대일 때도 공유되는지도 확인이 필요해요. (API-208)
5. **새 리포트 시간과 겹치는 작업**: 01:00에 다른 배치나 마이그레이션이 돌지 않는지, 그 시각까지 그날 결제 데이터가 다 들어와 있는지 확인해야 해요. 오늘 저녁 배포 직후 첫 실행에서 리포트가 두 번 돌거나 빠지지 않는지도 봐야 해요. (BATCH-07, DB-031)
