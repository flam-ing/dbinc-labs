# 내 업무 에이전트 설계서 · 예시

실습 3의 채운 예시예요. 실습 1에서 손으로 한 "배포 전 확인"을 에이전트에게 맡긴다고 생각하고 썼어요. 양식은 [../design/agent-design.md](../design/agent-design.md)예요.

## 0. 맡길 일

- 일 이름: 배포 전 변경 내역 점검
- 지금은 누가, 얼마나 자주, 몇 분 걸려요: 운영 담당자가 배포하는 날마다 손으로 해요. 30분쯤 걸려요.

## 1. 입력 · 무엇을 받아서 시작해요?

- 받는 것: 오늘 배포할 변경 내역 표
- 어디에 있어요: 배포 저장소의 `changes.md`

## 2. 도구 · 무엇을 읽고, 무엇을 써요?

- 읽기: `changes.md`, 변경 ID로 찾은 사내 이슈
- 쓰기: `deploy-check.md` 한 파일
- 하면 안 되는 것: 코드 고치기, 배포 명령 실행, 이슈 닫기

## 3. 판단 · 모델이 정해야 하는 곳은 어디예요?

- 모델이 정할 것: 서로 부딪히는 변경 찾기, 확인할 항목 다섯 줄 고르기
- 코드로 정할 것(합계, 정렬처럼 답이 하나인 일): 변경 ID 목록 뽑기, 영역별 개수 세기

## 4. 완료 · 무엇을 보면 끝났다고 해요?

- 결과물: 줄마다 변경 ID가 붙은 `deploy-check.md`
- 확인 방법: 훅이 모든 변경 ID가 한 번 이상 나왔는지 검사해요
- 사람이 승인할 곳: 배포 담당자가 읽고 배포 회의에 올려요

## 5. 운영 · 누가, 어디서, 언제 돌려요?

- 언제(트리거): 배포하는 날 17:00, 또는 `changes.md`가 바뀌었을 때
- 어디서(내 PC, 회사 서버, 클라우드): 회사 서버의 예약 작업
- 실패하면: 담당자에게 메신저로 알리고, 사람이 손으로 점검해요
