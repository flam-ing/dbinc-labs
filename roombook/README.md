# 회의실 예약 · 화면 뒤 API를 찾아 CLI로 만들기

2일차 5교시 [사내 시스템 연동](../../docs/day2-integration.md)에서 쓰는 연습용 사내 툴이에요. 회의실을 예약하는 작은 웹 화면이고, 공개 API 문서는 일부러 없어요. 화면이 뒤에서 부르는 요청을 찾아서, 그 요청을 쓰는 작은 CLI를 Claude와 같이 만들어 봐요. 회사, 사람, 전화번호, 예약은 모두 수업을 위해 지어낸 것이에요.

Python 표준 라이브러리만 써서 따로 설치할 것이 없어요. 서버를 끄면 예약은 처음 상태로 돌아가요.

## 켜는 법

Windows PowerShell에서 이 폴더로 가서 켜요.

```powershell
cd ~\dbinc-ai-course\labs\roombook
py app.py
```

macOS에서는 `py` 대신 `python3`으로 쳐요.

```bash
cd ~/dbinc-ai-course/labs/roombook
python3 app.py
```

`회의실 예약: http://127.0.0.1:8010`이 나오면 브라우저로 그 주소를 열어요. 끌 때는 터미널에서 `Ctrl+C`를 눌러요. 8010을 다른 프로그램이 쓰고 있으면 `py app.py --port 8011`처럼 다른 번호로 켜요.

## 화면에서 할 수 있는 것

| 메뉴 | 하는 일 |
| --- | --- |
| 회의실 현황 | 회의실 6개가 지금 쓰이는지, 다음 예약이 무엇인지 봐요 |
| 예약 목록 | 예약을 20건씩 봐요. 날짜로 거르거나 내 예약만 볼 수 있어요. 내 예약에는 취소 단추가 있어요 |
| 예약 만들기 | 회의실, 날짜, 시간, 제목을 골라 예약해요 |
| 직원 찾기 | 이름이나 팀으로 직원을 찾아요 |

브라우저에서 `F12`를 누르고 Network 탭을 열어 두면, 메뉴를 누를 때마다 화면이 부르는 `/api/...` 요청이 보여요.

## 확인 명령

서버가 제대로 켜지는지 보고 싶으면 이 명령을 돌려요. 빈 포트에 서버를 따로 켜서 검사하고 끝나면 꺼요.

```powershell
py smoke_test.py
```

마지막 줄이 `11/11 통과`면 돼요. 이미 켜 둔 서버를 검사하려면 `py smoke_test.py --url http://127.0.0.1:8010`으로 쳐요.

## 실습에서 보내는 문장

이 폴더를 Claude 데스크톱 앱의 Code 탭에서 열고 차례로 보내요. 서버는 PowerShell 창을 따로 열어 켜 둬요. 문장은 그대로 보내도 되고 내 말로 바꿔도 돼요.

1. 화면 뒤 요청 찾기(따라 하기 B): `app.py와 static 폴더를 읽고, 화면이 부르는 API를 주소·방법·주고받는 값 표로 정리해 줘. 고치지는 마.` 수업 툴이라 서버 코드(`app.py`)도 읽어요. 실제 사내 툴에는 서버 코드가 없어서 화면 코드와 F12 Network만 보고 찾아요.
2. 화면 규칙 찾기(따라 하기 C, 새 세션에서 Plan 모드): `화면 코드에서 막고 있는 규칙을 모두 찾아서, 서버도 막는지 표로 보여 줘.` 서버가 막는지는 수업 툴이라 볼 수 있어요. 실제 사내 툴에서는 서버가 막는지 모르니 화면 규칙을 모두 CLI가 지켜요.
3. CLI 만들기(실습 1, Accept edits 모드): `이 회의실 예약 화면을 쓰는 CLI를 만들어 줘. 로그인은 Edge나 Chrome 창을 띄워 내가 ID와 비밀번호를 직접 넣게 하고 쿠키만 저장해. 화면이 막는 규칙과 읽기 한도는 CLI도 똑같이 지켜.`
4. 로그인(실습 1): `로그인 명령을 실행해 줘. 창이 뜨면 내가 넣을게.` 창이 뜨면 그 창에 아이디와 비밀번호를 직접 넣어요. 채팅에는 쓰지 않아요. 로그인한 뒤 `내 예약 보여 줘`라고 보내요.
   읽기 한도(실습 1 더 해 보기): `CLI로 영업팀 직원을 모두 찾아 줘. 막히면 왜 막혔는지 알려 줘.` 다음에 `직원 찾기는 여러 번 불러도 하루에 30명까지만 보여 주게 홈 폴더에 센 값을 남겨 줘.`
5. 권한 규칙(실습 2): `방금 만든 CLI의 회의실 현황과 목록 보기는 묻지 말고, 예약과 취소와 직원 찾기는 매번 묻게 권한 규칙을 걸어 줘.`
6. 선택(실습 1이 빨리 끝나면): `이 CLI를 MCP 도구로도 쓸 수 있게 .mcp.json에 등록해 줘.` 파일 카드가 뜨면 **Accept**를 눌러요. 채팅에 "허락할게요"라고 써도 권한은 바뀌지 않아요.

## CLI를 만들 때 지킬 것

**로그인은 브라우저 창에서 사람이 해요.** CLI가 Edge(Windows)나 Chrome(macOS) 창을 띄우고, 내가 그 창에 아이디와 비밀번호를 직접 넣어요. CLI는 로그인 뒤 받은 쿠키만 내 홈 폴더의 숨김 폴더에 저장해요. 비밀번호는 CLI가 받지도, 파일에 저장하지도, 화면에 찍지도 않아요. 회사 시스템은 로그인 화면에 보안 단계가 더 붙어 있는 경우가 많아요. 사람이 브라우저에서 로그인하는 방식은 그런 곳에서도 대부분 통해요. 다만 CLI가 띄우는 창은 새 브라우저 프로필이라서, 회사 기기 인증을 요구하는 로그인은 막힐 수 있어요. 그때는 담당 부서에 물어봐요.

**화면이 막는 규칙은 CLI도 막아요.** 서버가 받아 준다고 해서 화면이 막는 일을 CLI로 하면 안 돼요. 화면에 없는 기능은 CLI에도 만들지 않아요. 화면에 보이지 않는 정보는 CLI도 보여 주지 않아요.

**읽기에도 한도를 둬요.** 쓰기만 조심하면 된다고 생각하기 쉬운데, 읽기도 회사 시스템에 부담을 주고 개인정보가 한꺼번에 빠져나가는 길이 돼요. CLI는 화면처럼 한 번에 20건씩 읽고, 한 번 실행에 읽는 쪽 수에 상한을 두고, 요청 사이에 잠깐 쉬어요. 서버가 429(너무 자주 읽었다는 응답)를 주면 `Retry-After`에 적힌 초만큼 기다렸다가 다시 해요. 전체 목록을 한 번에 긁어 가는 명령은 만들지 않아요. 한 번에 10명씩 지켜도 검색어를 나눠 여러 번 부르면 결국 전체를 읽을 수 있어요. 한 번 실행에 몇 번이라는 한도는 실행할 때마다 0부터 다시 세서, 나눠 부르면 막지 못해요. 그래서 여러 번 실행해도 합쳐서 세는 하루 상한도 같이 둬요. 예를 들면 직원 찾기는 하루 30명까지 보여 주고, 센 값은 쿠키 옆 홈 폴더 파일에 남겨요.

## 브라우저 창을 띄우는 데 필요한 것

CLI가 브라우저 창을 띄울 때는 `playwright` 패키지를 써요. 이미 깔린 Edge나 Chrome을 쓰니 브라우저를 따로 내려받지 않아도 돼요.

```powershell
py -m pip install playwright
```

macOS에서는 `python3 -m pip install playwright`로 쳐요. Homebrew Python처럼 설치가 막히면 이 폴더에 가상환경(`.venv`)을 만들고 그 안에 설치해요. Claude에게 "가상환경을 만들고 playwright를 깔아 줘"라고 부탁해도 돼요.

회사 PC라서 `pip` 설치가 막혀 있으면 차선책을 써요. CLI가 터미널에서 아이디를 묻고, 비밀번호는 `getpass`로 화면에 보이지 않게 입력받아 로그인 요청을 한 번 보내요. 받은 쿠키만 저장하고 비밀번호는 바로 버려요. 이 방식은 Claude가 실행하는 명령 안에서는 비밀번호를 받을 수 없어서, 내 PowerShell 창에서 직접 쳐야 해요. 로그인 화면에 보안 단계가 붙은 실제 회사 시스템에서는 잘 안 통해서, 수업에서는 브라우저 창 방식을 먼저 써요.

## 지켜야 할 것

실제 회사 시스템에 같은 방법을 쓸 때는 그 시스템의 이용 규칙과 회사 보안 정책을 먼저 확인해요. 공식 API나 내보내기 기능이 있으면 그것부터 써요. Network 탭에서 보이는 요청에는 로그인 쿠키가 들어 있어요. 쿠키 값을 Claude에게 붙여 넣거나 다른 사람에게 보내지 않아요.
