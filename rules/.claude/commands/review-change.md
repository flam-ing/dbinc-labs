현재 방명록 작업 사본의 변경을 검토하세요. 사용자의 추가 검토 관점: $ARGUMENTS

2. Git 저장소라면 status, diff, staged diff를 확인하세요. 새 파일은 diff에 없을 수 있으므로 status에 나온 관련 파일도 읽으세요. Git이 없으면 그 사실을 말하고 지정된 기준 사본과 비교하세요. Git 저장소를 만들거나 커밋하지 마세요.
3. 관련 코드에서 서버 입력 검증, 매개변수 SQL, textContent, 오류 표시, API 계약을 검토하세요.
