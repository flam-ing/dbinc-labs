# 방명록 예제

## 이게 무엇인가요

이름과 내용을 남기고, 목록을 보고, 서버를 다시 켜도 기록이 남는 작은 방명록이에요. Python 표준 라이브러리, SQLite(파일 하나에 저장하는 데이터베이스), HTML·CSS·JavaScript만 써서 따로 설치할 패키지가 없어요. 방명록을 만들거나 고칠 때 기준이 되는 API 약속과 확인 도구도 함께 들어 있어요.

## 켜는 법

이 파일이 있는 폴더에서 실행해요.

```bash
python3 app.py
```

터미널에 `방명록: http://127.0.0.1:8000 / DB: ...` 한 줄이 보이면 성공이에요.

브라우저에서 http://127.0.0.1:8000 을 열어요. 방명록 화면이 보이면 성공이에요. HTML 파일을 더블클릭해서 열면 API를 부를 수 없으니 꼭 이 주소로 열어요.

서버는 켠 터미널에서 `Ctrl+C`로 꺼요.

API를 직접 불러 보려면 서버를 켜 둔 채 새 터미널에서 실행해요.

```bash
curl -i http://127.0.0.1:8000/api/entries -H 'Content-Type: application/json' -d '{"name":"실습자","message":"첫 기록입니다"}'
```

`HTTP/1.0 201 Created`와 저장된 기록이 보이면 성공이에요.

```bash
curl http://127.0.0.1:8000/api/entries
```

방금 저장한 기록이 맨 앞에 있는 목록이 보이면 성공이에요.

## 확인하는 법

```bash
python3 smoke_test.py
```

실제 HTTP 요청으로 등록, 조회, 오류 응답, 서버 재시작 뒤 기록 유지, 막아야 할 파일 경로를 검사해요. 임시 포트와 임시 DB를 쓰기 때문에 켜 둔 서버와 기록은 건드리지 않아요.

마지막에 `Ran 3 tests`와 `OK`가 보이면 성공이에요. 첫 줄의 `검사 대상`이 내가 검사하려는 `app.py`인지도 확인해요.

다른 서버를 검사하는 방법이에요.

| 명령 | 검사 대상 |
| --- | --- |
| `python3 smoke_test.py --app 내파일.py` | 내 Python 서버. `--port`와 `--db` 옵션을 받아야 해요 |
| `python3 smoke_test.py --url 주소` | 이미 켜 둔 서버. 예: `http://127.0.0.1:8080` |

`--url`은 서버를 끄고 켜지 않아서 재시작 뒤 기록이 남는지는 직접 확인해야 해요. 이름이 '검사'로 시작하는 기록 3개도 그 서버의 DB에 남아요.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 서버가 켜지지 않아요 | 8000 포트를 이미 다른 곳에서 쓰고 있어요 | `python3 app.py --port 8001`로 켜고, 브라우저 주소의 포트도 8001로 바꿔요 |
| 화면은 열리는데 기록이 저장되지 않아요 | HTML 파일을 더블클릭해서 열었어요 | 서버를 켜고 http://127.0.0.1:8000 으로 열어요 |
| 검사가 늘 통과해요 | `--app`과 `--url`이 없으면 내 코드가 아니라 옆의 `app.py`를 검사해요 | 첫 줄의 `검사 대상`을 확인하고 `--app`이나 `--url`을 붙여요 |
| `--url` 검사가 404 단계에서 실패해요 | 화면 개발 서버(Vite, 5173)는 없는 경로에도 화면을 돌려줘요 | 화면 주소가 아니라 API 주소(예: `http://127.0.0.1:8080`)로 검사해요 |
| 기록이 모두 사라졌어요 | Docker에서 `docker compose down -v`가 volume(Docker가 따로 보관하는 저장 공간)까지 지워요 | 재시작 뒤 기록을 볼 때는 `-v`를 붙이지 않아요 |

다른 DB 파일을 쓰려면 `python3 app.py --db 경로`로 켜요. 기록은 기본으로 `data/guestbook.sqlite3`에 저장돼요.

## 더 알아보기

원본 `README.md`에 아래 내용이 더 있어요.

- API 약속: 응답 모양, 이름 1~40자와 내용 1~500자 검사, 오류 코드(400, 413, 415, 404)의 뜻
- Python으로 직접 만드는 방법(대체 경로)
- Docker로 실행하기: `docker compose up --build`, `docker compose restart`, `docker compose logs --tail 20`, `docker compose down`. 이 명령들은 이번에 실행해 보지 못해서 확인 필요예요.
- 파일별 역할: `app.py`(서버), `static/`(화면), `starter/`(시작 폴더), `REQUIREMENTS-PROMPTS.md`(단계별 요청 모음)
