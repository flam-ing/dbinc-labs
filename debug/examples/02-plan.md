## Claude의 답 (그대로)

원인은 `app.py:41`의 비교 연산자입니다. 아직 아무것도 고치지 않았고, 계획은 `~/.claude/plans/<계획 파일>.md`에 적어 뒀습니다.

## 확인한 사실
- `app.py:41`에 `if len(result[key]) >= maximum:`가 있습니다. `>=`라서 정확히 `maximum`자(이름은 40자)인 값도 거절합니다. 한계값 자체는 허용해야 하므로 `>`여야 합니다.
- 39자는 201, 40자와 41자는 400이 나오는 것을 실제 요청으로 확인했습니다.
- 화면 쪽은 정상입니다. `static/index.html:17`의 이름 칸은 `maxlength="40"`이라 40자까지 입력됩니다. 화면은 40자를 허용하는데 서버만 거절하는 어긋남입니다.
- 기존 테스트(`tests/test_guestbook.py`)에는 길이 경계를 검사하는 것이 없어서 이 버그를 못 잡았습니다.

## 아직 추측인 것
- 같은 루프가 내용(500자)에도 쓰이므로 내용 500자도 거절될 가능성이 큽니다. 직접 보내 보지는 않았습니다.
- 지금 `app.py:41`은 `strip()` 뒤의 길이를 잽니다. 앞뒤 공백을 포함해 40자를 넘는 입력은 이슈 범위 밖이라 따로 확인하지 않았습니다.

## 계획
1. **회귀 테스트 먼저:** `tests/test_bugs.py`를 새로 만들고, 이슈의 입력 그대로 `가`×40 + `안녕하세요`를 보내 201을 기대하는 테스트를 넣습니다. 41자 → 400 테스트도 함께 넣어 상한이 유지되는지 봅니다. 서버를 띄우는 방식은 `test_guestbook.py`의 것을 재사용합니다.
2. **고치기 전 실패 확인:** 지금 코드에서 40자 테스트가 실패하는지 확인합니다.
3. **수정:** `app.py:41`에서 `>=`를 `>`로 한 글자만 바꿉니다. 메시지와 다른 줄, 기존 테스트는 건드리지 않습니다.
4. **내용 500자:** 고치기 전에 먼저 재현해 보고, 같은 방식으로 테스트에 넣을지 정합니다. 재현되지 않으면 고치지 않습니다.
5. **검증:** `python3 -m unittest` 결과를 그대로 보여 주고, 서버를 켜서 40자 → 201, 41자 → 400을 다시 확인합니다.

이 환경에서는 계획 승인 도구(ExitPlanMode)를 쓸 수 없어서 승인 요청을 따로 띄우지 못했습니다. 이 계획대로 진행해도 되는지 알려 주세요.
