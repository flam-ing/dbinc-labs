# 2일차 4교시에 보내는 문장

방명록 폴더(`~/dbinc-debug`)로 Code 탭 세션을 열고 보내요. `<꺾쇠>` 안은 내 것으로 바꿔요. 이슈 글은 GitHub 이슈 화면에서 제목과 본문을 복사해 문장 아래에 붙여요. Windows는 문장 끝에 "py로 돌려 줘"를 붙여요.

모드는 Auto로 둬요. Auto가 없으면 Accept edits로 하고, 명령 카드는 읽고 허락해요.

## 실습 1 · 저장소 받고 켜 보기 (3분)

```text
서버를 켜고 테스트를 돌려 줘.
```

테스트 3개가 통과하면 돼요. 버그를 잡는 테스트가 아직 없어서 통과해요.

## 강사 시연 · 이슈 #1을 세 번에 나눠 고치기

따라 보내도 돼요. 강사 사본에서 실제로 보낸 문장이에요.

재현(Auto):

```text
아래 이슈를 재현 순서대로 재현해 줘. 서버를 켜서 실제로 요청을 보내 보고, 기대와 실제를 한 줄씩 말해 줘. 아직 고치지는 마.

<이슈 #1 제목과 본문>
```

결과는 [01-repro.md](01-repro.md)에 있어요.

원인(Plan, 같은 대화):

```text
원인을 찾아 줘. 확인한 사실과 아직 추측인 것을 나눠 주고, 원인 줄과 고칠 방법을 계획으로 보여 줘.
```

결과는 [02-plan.md](02-plan.md)에 있어요. Claude는 41행이라고 했지만 실제 원인 줄은 `app.py` 42행이에요.

고치기(Auto, 같은 대화):

```text
계획대로 그 줄만 고쳐 줘. 이슈 입력 그대로 회귀 테스트를 tests/test_bugs.py에 더하고, 고치기 전 코드에서는 그 테스트가 실패하는지도 보여 줘. 마지막에 python3 -m unittest 결과를 그대로 보여 줘.
```

결과는 [03-fix.md](03-fix.md)에 있어요. 고치기 전에는 40자 테스트가 실패했고, 고친 뒤에는 테스트 8개가 모두 통과했어요.

## 실습 2 · 이슈 #2 고치기 (5분)

```text
이 이슈를 재현하고 원인을 찾아서 한 줄로 고쳐 줘. 테스트도 하나 더해 줘.

<이슈 #2 제목과 본문>
```

이슈 #2는 10:42쯤 와요. 강사 사본에서는 조금 더 긴 문장으로 보냈어요. 26초 걸렸고, 그 줄만 고쳐서 테스트가 통과했어요. 기록은 [05-issue2.md](05-issue2.md)에 있어요.

Claude가 여러 줄을 고쳤으면 `/rewind`로 되감고 다시 보내요. 일찍 끝나면 아래 문장으로 SQL 주입을 알아봐요.

```text
고치기 전 코드에 따옴표를 이용해서 다른 글까지 지울 수 있었는지 설명만 해 줘. 실행하지는 마.
```

## 실습 3 · 고친 것 확인하고 커밋하기 (3분)

```text
바꾼 파일과 줄을 git diff로 보여 주고, 테스트를 다시 돌려 줘. 모두 통과하면 <이슈 번호>를 넣어 커밋해 줘. push는 하지 마.
```

ZIP으로 받았거나 폴더를 복사했다면 git 저장소가 아니에요. "git init부터 해 줘"라고 먼저 보내요. 이 문장은 미리 보내 보지 않았어요.

## 실습 4 · /goal로 남은 이슈 맡기기 (5분)

```text
/goal 아래 두 이슈(#3, #4)가 모두 고쳐지고, 이슈마다 회귀 테스트가 tests/test_bugs.py에 있고, python3 -m unittest가 실패 없이 끝나면 완료야. 기존 테스트는 고치지 마. 20턴이 넘으면 멈춰.

<이슈 #3, #4 제목과 본문>
```

도는 중에 `/goal`을 치면 상태를 볼 수 있어요. 그만두려면 `/goal clear`를 쳐요.

강사 사본에서는 44초 만에 두 이슈를 고쳤고 테스트 11개가 모두 통과했어요. 기록은 [08-goal.md](08-goal.md)에 있어요. #3은 화면 버그라서 Claude가 브라우저로 확인하지 못했어요. 끝나면 서버를 켜고 글을 남겨서 목록에 바로 나오는지 직접 봐요.

## 실습 5 · 루틴으로 맡길 일 골라 보기 (4분)

```text
내가 되풀이하는 일은 <내 일>이야. 이 일을 루틴으로 맡기면 좋을지, AI 없이 알림이나 스크립트로 충분한지 판단해 줘. 루틴은 만들지 마.
```

떠오르지 않으면 "매일 아침 실패 로그 읽기"를 넣어요. 이 문장은 미리 보내 보지 않았어요.

## 강사 시연 · 자동으로 돌리기

강사가 이슈 #2에 `autofix` 라벨을 붙이면 워크플로([claude.yml](../github/workflows/claude.yml))가 Claude를 깨워요. Claude는 고친 코드를 PR로 올리고, 머지는 사람이 해요. 라벨은 저장소에 쓰기 권한이 있는 사람만 붙일 수 있어요.

이 워크플로는 GitHub에서 끝까지 돌려 보지 않았어요. 리허설 때 한 번 돌려 봐요. 안 되면 루틴 요청문([routine-prompt.md](../routine-prompt.md))으로 미리 만든 PR 본문 [07-pr.md](07-pr.md)를 보여 줘요.

## 실습 6 · 버그 신고 하나 쓰기 (4분)

강사 저장소의 Issues에서 New issue를 누르고 버그 신고 양식을 골라요. 재현 순서, 기대, 실제 세 칸을 채우고 Submit을 눌러요. 쓰기 어려우면 아래 문장으로 초안을 받아요. 이 문장은 미리 보내 보지 않았어요.

```text
방명록을 쓰다가 <이상했던 점>을 봤어. 버그 신고로 쓸 수 있게 재현 순서, 기대, 실제 세 칸으로 정리해 줘. 원인은 쓰지 마.
```

GitHub 계정이 없으면 수업 채팅방에 세 칸으로 써서 올려요.
