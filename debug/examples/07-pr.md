## Claude가 쓴 PR (PR.md 그대로)

제목: fix: [DB] 내용에 작은따옴표(')가 있으면 저장이 안 돼요 (#1)

Closes #1

## 원인
`app.py:97-100`의 `do_POST`가 INSERT 문을 f-string으로 만들어 `'{entry['message']}'`처럼 값을 SQL에 직접 붙였다. 값에 `'`가 있으면 SQL 문자열이 중간에 닫혀 `sqlite3.Error`(문법 오류)가 나고, 이를 잡는 `except`가 "저장하지 못했습니다" 500을 돌려줬다. 같은 구조라 SQL 주입에도 열려 있었다.

## 바꾼 줄
`app.py:98-100`: f-string 대신 `VALUES (?, ?, ?)`와 값 튜플 `(name, message, created_at)`로 바인딩했다. 다른 줄은 건드리지 않았다.
`tests/test_bugs.py` 신규: 이슈 입력(이름 `김디비`, 내용 `오늘 회의 '정말' 좋았어요`)을 그대로 POST하고 201과 목록 조회 결과를 확인한다.

## 실행한 명령과 결과
- 수정 전 재현: 임시 서버(포트 8765)에 위 입력을 POST → 기대 201, 실제 `500 {"error": "저장하지 못했습니다. 다시 시도해 주세요."}`.
- 수정 전 `python3 -m unittest tests.test_bugs.Issue1QuoteTest.test_message_with_single_quotes_is_saved` → `AssertionError: 500 != 201`, FAILED (failures=1).
- 수정 후 `python3 -m unittest` → `Ran 7 tests ... OK`. (`Issue1QuoteTest`가 `GuestbookTest`를 상속해 기존 테스트가 한 번 더 도는 것까지 7개. ResourceWarning 경고가 출력되지만 실패는 아니다.)

## 확인하지 못한 것
- 브라우저에서 화면으로 직접 누르는 확인은 하지 않았다. 같은 API 요청으로만 확인했다.
- 다른 이슈(BUG-2~4)는 이번 범위가 아니라 다루지 않았다.

## Claude의 마지막 답 (그대로)

이슈 #1을 고쳐서 `claude/issue-1` 브랜치에 로컬 커밋(`4cff6ba`)으로 남겼고, 전체 테스트는 7개 모두 통과했습니다. 브라우저로 직접 눌러 보지는 않고, 같은 API 요청으로만 확인했습니다.

- **재현:** 이슈의 입력(`김디비`, `오늘 회의 '정말' 좋았어요`)을 POST하면 201이 나와야 하는데 500과 "저장하지 못했습니다"가 나왔습니다.
- **원인:** `app.py`의 `do_POST`가 INSERT 문을 f-string으로 만들어 값을 SQL에 그대로 붙이고 있었습니다. 값에 `'`가 있으면 SQL 문법 오류가 나고, 그 오류를 잡는 `except`가 500을 돌려줬습니다.
- **수정:** `app.py` INSERT 한 문장만 `VALUES (?, ?, ?)`와 값 튜플로 바꿨습니다.
- **회귀 테스트:** `tests/test_bugs.py`를 새로 만들어 이슈 입력을 그대로 POST하고, 201과 목록에 저장된 내용을 확인합니다. 수정 전 코드에서는 `AssertionError: 500 != 201`로 실패하는 것을 확인했습니다.
- **전체 테스트:** 수정 후 `python3 -m unittest`가 `Ran 7 tests ... OK`였습니다. 새 테스트 클래스가 기존 `GuestbookTest`를 상속해서, 기존 테스트가 한 번 더 도는 것까지 7개입니다. 실행 중 `ResourceWarning`이 나오지만 실패는 아닙니다.

PR 제목과 본문은 `PR.md`에 CLAUDE.md의 PR 규칙대로 썼습니다. `PR.md`는 커밋에 넣지 않았고, push, PR 생성, 이슈 댓글, 라벨 제거는 하지 않았습니다.
