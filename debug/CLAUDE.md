# 방명록(디버깅 실습판) 작업 지침

## 프로젝트 사실

- Python 표준 라이브러리 HTTP 서버(`app.py`), SQLite, 화면(`static/index.html`, `static/app.js`)으로 된 교육용 방명록이다. 설치할 패키지는 없다.
- 실행: `python3 app.py` → http://127.0.0.1:8000. 켤 때 첫 줄에 주소와 DB 위치를 찍는다.
- 테스트: `python3 -m unittest`. 서버를 임시 포트와 임시 DB로 띄워서 검사한다.
- 버그 신고는 GitHub Issues로 들어온다. 영역은 화면, 서버, DB, 실행 환경이다. 대화에서는 사람이 이슈 글을 붙여 넣어 준다.

## 버그를 고칠 때

- 먼저 이슈의 재현 순서대로 재현하고, 기대와 실제를 한 줄씩 적는다. 재현되지 않으면 고치지 않는다.
- 원인은 한 번에 하나씩, 필요한 줄만 고친다.
- 고친 버그마다 이슈의 입력을 그대로 쓴 회귀 테스트를 `tests/test_bugs.py`에 더한다. 고치기 전 코드에서 그 테스트가 실패하는지 확인한다. 화면 버그처럼 자동 테스트가 어려우면 브라우저에서 확인하는 순서를 적는다.
- 기존 테스트를 지우거나 기대값을 바꿔서 통과시키지 않는다.
- 예외를 잡아서 숨기지 않는다. 새 패키지를 추가하지 않는다.
- 끝나면 `python3 -m unittest` 결과를 그대로 보여 준다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.

## PR 규칙(자동화 저장소에서)

- 브랜치 이름은 `claude/issue-<번호>`다. 기본 브랜치에 직접 push하지 않는다.
- PR 제목은 `fix: <이슈 제목> (#번호)`, 본문 첫 줄은 `Closes #번호`다.
- 본문에는 원인(파일과 줄), 바꾼 줄, 실행한 명령과 결과, 확인하지 못한 것을 순서대로 적는다.
