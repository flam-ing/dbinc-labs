# 카페 포인트(디버깅 실습판) 작업 지침

## 프로젝트 사실

- 동네카페의 하루 마감 프로그램이다. Python 표준 라이브러리만 쓰고, 설치할 패키지는 없다.
- 실행: 폴더 맨 위에서 `python3 cafe.py`(Windows는 `py cafe.py`). `data/members.csv`(회원 명부)와 `data/orders.csv`(오늘 주문)를 읽고, 영수증을 화면에 찍고, `out/members.csv`와 `out/report.txt`를 쓴다.
- 규칙: 결제 금액의 1%를 포인트로 쌓고 VIP는 3%다. 1점 미만은 버린다. 누적 결제가 100,000원 이상이면 VIP가 된다. 생일 달 첫 주문이 5,000원 이상이면 3,000원을 깎아 준다. 포인트는 1,000점부터 쓴다.
- Windows에서는 영수증 한글이 깨지지 않게 `py -X utf8 cafe.py`, `py -X utf8 -m unittest`로 돌린다.
- 테스트: `python3 -m unittest`(Windows는 `py -m unittest`). `tests/cafe_runner.py`의 `run_cafe`가 임시 폴더에 명부와 주문을 만들고 `cafe.py`를 돌린다.
- 버그 신고는 GitHub Issues로 들어온다. 영역은 등급, 적립, 쿠폰, 마감이다. 대화에서는 사람이 이슈 글을 붙여 넣어 준다.

## 버그를 고칠 때

- 먼저 이슈의 재현 순서대로 재현하고, 기대와 실제를 한 줄씩 적는다. 재현되지 않으면 고치지 않는다.
- 재현하려고 `data/` 원본을 바꾸지 않는다. 주문 줄을 더해야 하면 `run_cafe`나 임시 폴더 사본을 쓴다.
- 원인은 한 번에 하나씩, 필요한 줄만 고친다.
- 고친 버그마다 이슈의 입력을 그대로 쓴 회귀 테스트를 `tests/test_bugs.py`에 더한다. 고치기 전 코드에서 그 테스트가 실패하는지 확인한다.
- 기존 테스트를 지우거나 기대값을 바꿔서 통과시키지 않는다.
- 예외를 잡아서 숨기지 않는다. 새 패키지를 추가하지 않는다.
- 끝나면 `python3 -m unittest` 결과를 그대로 보여 준다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.

## PR 규칙(자동화 저장소에서)

- 브랜치 이름은 `claude/issue-<번호>`다. 기본 브랜치에 직접 push하지 않는다.
- PR 제목은 `fix: <이슈 제목> (#번호)`, 본문 첫 줄은 `Closes #번호`다.
- 본문에는 원인(파일과 줄), 바꾼 줄, 실행한 명령과 결과, 확인하지 못한 것을 순서대로 적는다.
