# 매일 실행 요청문

하루치 일은 `price-watch-daily` 스킬에 적어 두었어요. 아래 요청문은 그 스킬을 매일 부르는 방법이에요.
어디서 돌리느냐에 따라 닿을 수 있는 곳이 달라요.

| 어디서 | 연습몰(내 PC 127.0.0.1)에 닿나요 | 가장 짧은 간격 | 이 실습에서 |
| --- | --- | --- | --- |
| `/loop` (열어 둔 Claude Code 세션 안) | 닿아요 | 1분 | 수업 중 시연 |
| 데스크톱 앱의 로컬 예약 작업(Routines → New routine → Local) | 닿아요. 앱이 켜져 있고 PC가 깨어 있어야 해요 | 1분 | 수업 뒤 내 PC에서 |
| 클라우드 루틴(Routines → New routine → Cloud, `/schedule`) | 닿지 않아요. 클라우드에서 저장소를 새로 받아 돌아요 | 1시간 | 회사에 돌아가서 실제 대상으로 |

## A. 수업 중: /loop로 하루씩 넘기며 돌리기

연습몰은 시뮬레이션이라 날짜를 넘겨야 다음 날 가격이 나와요. Claude Code 입력창에 이렇게 넣어요.

```text
/loop 2m python3 tools/sim_day.py next 로 연습몰 날짜를 하루 넘긴 다음, price-watch-daily 스킬 순서대로 하루치 일을 해 줘. sim_day.py가 30일보다 뒤로 못 간다고 하면 아무것도 하지 말고 "끝"이라고만 말해.
```

멈출 때는 "예약 작업 목록 보여 줘", "그 작업 취소해 줘"라고 말해요.

## B. 수업 뒤: 데스크톱 앱 로컬 예약 작업

Instructions 칸에 넣을 글이에요. 작업 폴더는 이 폴더를 고르고, 처음에는 **Run now**로 한 번 돌려서 권한 질문에 답해 둬요.

```text
이 폴더에서 price-watch-daily 스킬 순서대로 오늘 하루치 가격 추적을 해 줘.
연습몰 서버(http://127.0.0.1:8766)가 꺼져 있으면 아무것도 고치지 말고 "서버 꺼짐"이라고만 보고해.
```

## C. 회사에서: 클라우드 루틴 요청문 예시

클라우드 루틴은 GitHub 저장소를 새로 받아서 돌고, 기본 환경은 허용된 도메인에만 나갈 수 있어요.
그래서 실제로 쓰려면 수집해도 되는 대상인지(약관, 회사 승인)를 먼저 확인하고, 그 주소를 환경의 허용 도메인에 넣어야 해요.
collect.py의 `ensure_local`도 그 주소에 맞게 바꿔야 해요. 연습몰 주소로는 동작하지 않아요.

```text
이 저장소의 price-watch-daily 스킬 순서대로 오늘 하루치 가격 추적을 해 줘.
price-watch-rules 스킬의 금지 규칙을 지켜.
수집이 성공한 평범한 날에는 리포트만 다시 만들고 짧게 끝내.
구조 변경으로 파서를 고쳤다면 테스트가 모두 통과한 경우에만 claude/ 로 시작하는 브랜치에 커밋하고,
고친 내용과 selector-changes.md에 더한 기록을 요약해 줘. main에는 직접 넣지 마.
숫자는 스크립트 출력에서만 가져와.
```
