# 내 루틴 요청문 초안 (실제 답, 선택 심화)

2일차 4교시 부록의 선택 심화 "내 루틴 하나 설계"를 끝냈을 때의 모습이에요. 표를 내 일로 채운 `my-routine.md`를 Claude에게 주고 루틴 요청문 초안을 받았어요. 루틴은 만들지 않았어요.

## 준비한 표 `my-routine.md`

[my-routine-example.md](my-routine-example.md)의 예시 1을 "내 일" 칸 하나짜리 표로 옮겼어요.

| 칸 | 내 일 |
| --- | --- |
| 할 일 | 평일 아침, 지난밤 실패한 배치 로그를 읽고 원인 후보를 이슈로 남기기 |
| 트리거 | 예약, 평일 08:30 |
| AI가 필요한 이유 | 로그 수백 줄을 읽고 비슷한 실패끼리 묶어 원인 후보를 고르는 일 |
| AI 없이 할 부분 | 실패 로그 파일이 있는지는 스크립트가 먼저 확인 |
| 범위 | 배치 저장소 하나, 커넥터 없음 |
| 할 일이 없을 때 | "실패 로그가 없으면 '처리할 일 없음' 한 줄만 남기고 끝내" |
| 사람의 승인 | 만든 이슈를 사람이 읽고 담당을 정해요 |
| 끄는 때 | 그 배치를 없애는 날 |

## 보낸 말

`prompts.md` 6번 그대로예요. 모드는 Manual이에요. 파일을 고치지 않고 답만 받아요.

```text
my-routine.md의 표를 읽고 루틴 요청문 초안을 써 줘. 할 일이 없으면 "처리할 일 없음" 한 줄만 남기고 끝내는 줄, 한 번에 하나만 처리하는 줄, 사람이 정할 일은 남겨 두는 줄을 꼭 넣어 줘. 루틴은 아직 만들지 마.
```

2026-10-17, Claude Code 2.1.302, 모델 Sonnet 5.5. 걸린 시간 11초, 주고받은 횟수 2번이에요.

## Claude가 쓴 초안 (원문 그대로)

```text
너는 평일 아침 배치 실패를 점검하는 루틴이다. 이 배치 저장소 하나만 다루고, 외부 커넥터는 쓰지 않는다.

[할 일]
지난밤에 실패한 배치 로그를 읽고, 비슷한 실패끼리 묶어서 원인 후보를 고른다.
묶음마다 이슈를 하나씩 남기고, 이슈에는 아래 내용을 적는다.
- 실패한 로그 위치와 대표 오류 줄
- 원인 후보와 그렇게 본 근거

[할 일이 없을 때]
실패 로그가 없으면 '처리할 일 없음' 한 줄만 남기고 끝낸다. 이슈는 만들지 않는다.

[한 번에 하나만]
한 번 실행할 때 실패 묶음 하나만 처리하고 멈춘다. 나머지는 다음 실행에서 이어서 본다.

[사람이 정할 일]
- 담당자는 지정하지 않는다. 담당은 사람이 이슈를 읽고 정한다.
- 원인은 확정하지 않고 "후보"로만 쓴다.
- 코드, 설정, 배치 일정은 고치지 않는다.
```

## Claude가 짚은 점 (원문에서 두 가지)

- **스크립트와 루틴의 역할 나눔**: 표에 "실패 로그 파일이 있는지는 스크립트가 먼저 확인"이라고 되어 있습니다. 그래서 요청문에는 파일 확인 단계를 넣지 않았습니다. 스크립트가 파일이 없을 때 '처리할 일 없음'을 남기고 끝낼지, 루틴이 그 줄을 쓸지는 정해야 합니다.
- **"한 번에 하나만"의 기준**: 표에 없던 줄이라 "실패 묶음 하나"로 잡았습니다. "이슈 하나"나 "로그 파일 하나"로 바꾸고 싶으면 알려 주세요.

마지막에 "예약(평일 08:30)과 '그 배치를 없애는 날 끈다'는 요청문이 아니라 루틴 설정에서 정할 내용이라 요청문에서 뺐습니다"라고도 했어요. 세 번째로 짚은 점은 준비할 때 표에 구분선이 두 줄 들어간 실수를 알려 준 것이라 여기서는 뺐어요.

## 볼 점

- 부탁한 세 줄(할 일 없으면 끝, 한 번에 하나, 사람이 정할 일)이 모두 들어갔어요.
- 표에 없던 기준("실패 묶음 하나")은 Claude가 정하고 바꿀지 물었어요. 이런 곳은 내가 정해서 요청문에 적어요.
- 예약 시각과 끄는 날은 요청문이 아니라 루틴 만들기 화면에서 정해요.
- 회사 저장소나 회사 시스템에 실제로 걸 때는 보안 담당과 저장소 관리자의 승인을 먼저 받아요.
