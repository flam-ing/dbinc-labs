# 내 루틴 설계 예시

루틴이 도는 동안 내 업무에 걸 루틴을 하나 설계해요. 만들지 않아도 되고, 아래 표를 내 일로 바꿔 `my-routine.md`에 채우면 돼요. 예시 두 개를 적었어요. 하나는 AI가 꼭 필요한 일이고, 하나는 AI 없이 해도 되는 일이에요.

## 예시 1: 평일 아침 실패 로그 요약 (AI가 필요해요)

| 칸 | 적을 것 | 예 |
| --- | --- | --- |
| 할 일 | 매일이나 매주 되풀이하는 일 하나 | 평일 아침, 지난밤 실패한 배치 로그를 읽고 원인 후보를 이슈로 남기기 |
| 트리거 | 예약(최소 한 시간 간격), API, GitHub(PR과 릴리스 이벤트만) | 예약, 평일 08:30 |
| AI가 필요한 이유 | 사람이나 스크립트로는 안 되는 판단 | 로그 수백 줄을 읽고 비슷한 실패끼리 묶어 원인 후보를 고르는 일 |
| AI 없이 할 부분 | 확인만 하는 일은 스크립트로 | 실패 로그 파일이 있는지는 스크립트가 먼저 확인 |
| 범위 | 저장소, 커넥터 | 배치 저장소 하나, 커넥터 없음 |
| 할 일이 없을 때 | 바로 끝내는 줄 | "실패 로그가 없으면 '처리할 일 없음' 한 줄만 남기고 끝내" |
| 사람의 승인 | 어디서 사람이 정하나 | 만든 이슈를 사람이 읽고 담당을 정해요 |
| 끄는 때 | 언제 끄거나 지우나 | 그 배치를 없애는 날 |

## 예시 2: PR이 열리면 체크리스트 리뷰 (AI가 필요해요)

| 칸 | 예 |
| --- | --- |
| 할 일 | PR이 열릴 때마다 팀 체크리스트(테스트 추가, 비밀값 없음, 문서 갱신)로 1차 리뷰 댓글 남기기 |
| 트리거 | GitHub, PR이 열릴 때 |
| AI가 필요한 이유 | 바뀐 코드를 읽고 체크리스트 항목마다 지켰는지 판단 |
| AI 없이 할 부분 | 파일 이름 규칙, 줄 길이는 린터로 |
| 범위 | 저장소 하나, 커넥터 없음 |
| 할 일이 없을 때 | 문서만 바뀐 PR이면 "확인할 코드 없음" 한 줄만 |
| 사람의 승인 | 머지는 사람이 해요 |
| 끄는 때 | 팀이 다른 리뷰 도구로 바꾸는 날 |

## AI 없이 해도 되는 일 (루틴을 걸지 않아요)

| 할 일 | 왜 AI가 필요 없나 | 대신 |
| --- | --- | --- |
| "auto-fix 라벨 붙은 이슈가 있나" 매시간 확인 | 있다, 없다만 보면 돼요 | GitHub Actions의 이슈 이벤트나 짧은 스크립트 |
| 매일 같은 표를 같은 폴더로 복사 | 판단이 없어요 | 운영체제 예약 작업 |

## 요청문 초안 받기 (더 해 보기)

표를 채운 다음 Claude에게 초안을 부탁해요. 문장은 `prompts.md` 6번에 있어요. 회사 저장소나 회사 시스템에 실제로 걸 때는 보안 담당과 저장소 관리자의 승인을 먼저 받아요.
