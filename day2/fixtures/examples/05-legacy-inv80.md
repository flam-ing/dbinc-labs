# 실제 답 5: 레거시의 열린 버그로 해 보기 (inventory-py, INV-80)

예시 버그 대신 1일차에 맡은 레거시의 열린 버그로 하는 사람을 위한 견본이에요. `prompts.md` 맨 아래 "레거시로 할 때"의 두 문장을 inventory-py의 INV-80으로 실제로 보냈을 때 Claude가 한 말이에요. Claude가 한 말은 고치지 않고 그대로 옮겼어요.

INV-80은 "요약의 '판매자료 오류'가 늘 0줄이에요"라는 열린 버그예요. 판매 파일에 이상한 줄이 있어도 리포트 맨 끝에는 늘 `판매자료 오류 0줄`로 나와요.

- 날짜: 2026-10-17
- 모델: Sonnet 5.5 (`claude-sonnet-5-5`)
- 폴더: `labs/legacy/inventory-py` 사본. 1일차 5교시에 `/init`으로 만든 `CLAUDE.md`를 넣고 "받은 그대로"로 첫 커밋을 해 둔 상태예요.
- 1번 문장: Manual 자리(명령 실행만 허락), 14초, 주고받은 횟수 5
- 2번 문장: Plan 모드, 같은 대화에서 이어서, 28초, 주고받은 횟수 4
- 두 번 모두 소스 파일은 하나도 바뀌지 않았어요.

> **참고** 이 `CLAUDE.md`에는 INV-80의 원인이 이미 한 줄 적혀 있었어요. 1일차 5교시의 `/init`이 코드를 읽고 적어 둔 거예요. 내 `CLAUDE.md`에 이런 줄이 없으면 Claude가 코드를 더 읽고, 시간도 조금 더 걸려요.

## 1. 재현하고 세 칸으로 나누기

### 보낸 말

```text
issues/INV-80.md를 읽고, 증상이 나오는 입력을 data 폴더에서 찾아 원본을 실행해 줘. 입력, 기대, 실제 세 칸으로 정리해 줘. 아직 아무것도 고치지 마.
```

Claude가 실행한 명령은 `ls data`, `grep`, `sed`, `awk`(이상한 줄 찾기), 그리고 원본 실행 `cd src && python3 reorder.py ../data/stock.csv ../data/sales.csv ../data/suppliers.csv 2015-11-02 ../out`이에요. Manual이면 명령마다 카드가 떠요. 명령을 읽고 **Allow once**를 눌러요.

### Claude의 답

````markdown
INV-80 증상이 재현돼요. 수정은 하지 않았어요. 실행으로 `out/`이 생겼지만 `.gitignore`에 있어서 git status는 깨끗해요.

| 입력 | 기대 | 실제 |
| --- | --- | --- |
| `data/sales.csv`, 기준일 2015-11-02 (나머지 인자는 `stock.csv`, `suppliers.csv`, 출력 `../out`)<br>수량이 이상한 줄 두 개가 집계 기간(2015-10-03~11-01) 안에 있어요.<br>• 91행: `2015-10-14,W02,C-3001,1O` (수량 `1O`, 숫자 1이 아니라 알파벳 O)<br>• 116행: `2015-10-20,W01,A-1002,` (수량이 빔) | 리포트 맨 끝에 `판매자료 오류 2줄` | 리포트 맨 끝에 `판매자료 오류 0줄` (종료 코드 0, 발주 파일은 정상 생성) |

- **원인:** `load_sales()`는 두 줄 모두 `int()`에서 예외가 나서 `BAD_LINES`를 올려요. 같은 입력에서 `invlib.BAD_LINES`를 직접 확인하면 2였어요. `reorder.py`는 `from invlib import *`로 import 시점의 값 0만 복사해 가서, `reorder.py:203`의 `print`가 늘 0을 찍어요. CLAUDE.md에 적힌 설명과 일치해요.
- **판매 합계:** 이 두 줄은 합계에서 빠지고, 이슈 댓글대로 다른 계산에는 영향이 없어요.
- **sales_empty.csv:** 헤더만 있는 파일이라 오류 줄이 없어서 이 증상과 관계없어요.
````

### 볼 곳

- 기대 칸을 코드가 아니라 데이터에서 채웠어요. 판매 파일에서 수량이 빈 줄과 `1O`(숫자 1 대신 영문 O) 줄을 직접 찾아서 "2줄이어야 한다"고 했어요.
- "아직 아무것도 고치지 마"를 지켰어요. 실행 결과 폴더 `out/`이 생긴 것까지 따로 알려 줬어요.

## 2. 고치는 계획과 바뀔 출력 예측 (Plan 모드)

### 보낸 말

모드 선택기에서 **Plan**을 고르고 같은 대화에서 보냈어요.

```text
INV-80을 고치는 단계별 계획을 세워 줘. 단계마다 바꿀 줄과, 고치면 원본 출력에서 어느 줄이 어떻게 바뀌는지 예측해 줘. 이슈의 결정(보류, 의도된 동작)도 확인해 줘.
```

### Claude의 답

답 첫 줄의 계획 파일 경로에서 강사 PC의 사용자 이름만 `…`로 줄였어요. "plan 승인 도구가 없어서"는 화면 없이 실행해서 나온 말이에요. 데스크톱 앱에서는 이 자리에 계획 승인 카드가 떠요.

````markdown
INV-80 수정 계획을 `/Users/…/.claude/plans/inv-80-nifty-boot.md`에 썼어요. 코드는 아직 안 고쳤어요. 이 환경에는 plan 승인 도구가 없어서, 승인은 이 대화에서 직접 받을게요.

**이슈 결정 확인**
- INV-80은 열림 상태에 우선순위 낮음이고, 보류나 의도된 동작이라는 기록이 없어요. 박준서가 원인을 찾으면 고치겠다고 했어요.
- INV-57, 63, 71, 78과는 관계없어요. 창고별 계산과 발주 파일 형식을 건드리지 않아서 구매팀장 승인 대상은 아니에요.
- 리포트 숫자가 0에서 실제 값으로 바뀌어요. 구매팀은 이 줄을 믿지 말라고 안내받았으니, 배포 전에 한 줄만 알려 주는 게 좋아요.

**단계**
1. `src/reorder.py`의 24행 근처(`from invlib import *` 아래)에 `import invlib`를 추가해요.
2. `src/reorder.py:203`에서 `% BAD_LINES`를 `% invlib.BAD_LINES`로 바꿔요. 문구와 형식은 그대로예요.
   - `BAD_LINES`를 `CNT['bad']`로 옮기는 방법도 있지만, `invlib.py`의 세 곳을 건드려서 택하지 않았어요.
3. (선택) 문서를 따로 커밋해요. 대상은 CLAUDE.md의 전역 상태 문단, `wiki/py3-migration-2015.md:39`("원인을 못 찾았다"), 이슈 상태예요.

**출력 변화 예측** (기준일 2015-11-02)
- `판매자료 오류 0줄`이 `판매자료 오류 2줄`로 바뀌어요. 바뀌는 건 이 한 줄뿐이에요.
- 발주 건수(4/4/3), 합계(11건 442개 1,882,050원), 제외 건수(1/2/1)는 그대로예요.
- `PO_20151102.csv`도 그대로예요. 오류 두 줄은 이미 판매 합계에서 빠지고 있었어요.
- `sales_empty.csv`는 오류 줄이 없어서 계속 0줄이에요.

**검증:** 고치기 전과 후에 같은 입력으로 리포트와 발주 파일을 만들어 `diff`로 비교해요. 리포트는 위 한 줄만 달라야 하고, 발주 파일은 바이트까지 같아야 해요.

이대로 진행할까요?
````

### 볼 곳

- 고치기 전에 이슈의 결정부터 확인했어요. 레거시 이슈 중에는 "일부러 그랬어요"처럼 고치지 않기로 한 것이 있어서, 이 확인이 꼭 필요해요.
- 바꿀 줄이 두 줄뿐이고, 더 크게 고치는 방법은 왜 고르지 않았는지도 적었어요.
- "원본 출력에서 어느 줄이 바뀌는지"를 한 줄로 예측했어요. 이 예측이 고친 뒤의 확인 기준이 돼요.
- 리포트 숫자가 바뀌면 그 숫자를 쓰는 사람(구매팀)에게 미리 알리자고 했어요. 코드 밖의 사람까지 챙기는 것이 레거시를 고칠 때 중요한 점이에요.

## 강사가 직접 확인한 것

계획의 1, 2단계를 사본에서 그대로 고치고, 같은 입력으로 고치기 전과 후를 만들어 비교했어요.

```text
$ diff before/report.txt after/report.txt
26c26
< 판매자료 오류 0줄
---
> 판매자료 오류 2줄
$ cmp before/PO_20151102.csv after/PO_20151102.csv && echo 같음
같음
```

예측대로 리포트의 26번째 줄 하나만 바뀌고 발주 파일은 그대로였어요. 이 수업에서는 레거시의 원본을 고치지 않아요. 고칠지는 이슈를 보고 팀이 정할 일이라서, 계획과 예측까지가 목표예요.
