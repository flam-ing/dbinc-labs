# 세 칸 견본: 입력, 기대, 실제

"오류율이 이상해요" 같은 버그 신고를 세 칸으로 나눈 견본이에요. 기대 칸은 코드가 아니라 명세(`SPEC.md`)와 데이터로 채워요. 코드에서 가져오면 버그까지 같이 가져와요.

괄호 안은 차례로 (오류 수, 오류율 %, 느린 요청 수)예요. 실제 칸은 `python tools/reproduce.py --impl work/debug/report.py`의 출력 그대로예요. 같은 출력이 `fixtures/debug.log`에도 있어요.

## billing

| 칸 | 내용 |
| --- | --- |
| 입력 | `fixtures/events.json` 8건 중 `service="billing"` 3건(200, 500, 503 / 120ms, 500ms, 900ms) |
| 기대 | 오류는 500 이상인 2건, 오류율은 2 ÷ 3 = 66.67%, 느린 요청은 500ms 이상인 2건. (2, 66.67, 2) |
| 실제 | `FAIL 오류 비율의 분모: actual=(2, 25.0, 1) expected=(2, 66.67, 2)` |

## catalog

| 칸 | 내용 |
| --- | --- |
| 입력 | `service="catalog"` 3건(200, 404, 200 / 90ms, 499ms, 500ms) |
| 기대 | 404는 오류가 아니라서 오류 0건, 오류율 0.0%, 500ms는 느린 요청이라 1건. (0, 0.0, 1) |
| 실제 | `FAIL 404와 500ms 경계: actual=(1, 12.5, 0) expected=(0, 0.0, 1)` |

## 없는 서비스

| 칸 | 내용 |
| --- | --- |
| 입력 | `service="unknown"`(데이터에 없는 이름) |
| 기대 | 명세 "필터 결과가 0건이면 수량은 0, 비율과 평균은 0.0"대로 (0, 0.0, 0) |
| 실제 | `ERROR 없는 서비스: ZeroDivisionError: division by zero` |

## 더 해 보기: identity

`reproduce.py`에는 없는 사례예요. 직접 세 칸을 채워 보고 아래와 견줘요.

| 칸 | 내용 |
| --- | --- |
| 입력 | `service="identity"` 2건(401, 500 / 80ms, 600ms) |
| 기대 | 401은 오류가 아니라서 오류 1건, 오류율 1 ÷ 2 = 50.0%, 느린 요청 1건. (1, 50.0, 1) |
| 실제(버그가 든 코드) | (2, 25.0, 1). 401도 오류로 세고, 2를 전체 8건으로 나눴어요 |
