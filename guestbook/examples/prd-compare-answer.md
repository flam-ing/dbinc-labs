# PRD와 비교시킨 답 (실제로 온 답)

6절 실습에서 보낸 문장과, 리허설에서 Claude가 실제로 보낸 답 그대로예요. 화면 변경을 아직 커밋하지 않은 상태에서 보냈어요. 내 답은 내 코드에 따라 달라요.

```text
첫 커밋부터 지금까지 바뀐 내용을 git으로 보고, PRD.md와 다르게 동작하는 곳이 있는지 찾아 줘.
고치지는 말고 목록으로만 알려 줘.
```

---

코드를 읽어서만 확인했어요. 서버를 켜거나 확인 도구를 돌리지는 않았어요. 참고로 `web/` 폴더는 아직 커밋되지 않았어요(untracked). 그래서 `git diff`에는 서버(`api/`)만 나오고, 화면 코드는 파일을 직접 열어서 봤어요.

## PRD와 다르게 동작하는 곳

1. **팀원이 링크로 들어올 수 없어요** (`web/vite.config.js:7`)
   - PRD에는 "팀 10명 안팎이 링크 하나로 바로 써요"라고 되어 있어요.
   - 그런데 화면 서버(Vite)에 `host` 설정이 없어서 기본값인 `localhost`에서만 열려요. 그래서 다른 팀원 PC에서는 접속이 안 돼요.
   - 서버(Spring)도 정적 파일을 내보내지 않아요(`spring.web.resources.add-mappings=false`). 그래서 서버 주소 하나만 팀원에게 알려 주는 방법도 지금은 없어요.

2. **화면이 글자 수를 서버와 다르게 세요** (`App.jsx:114,124,134,139`)
   - 서버는 실제 글자 수(code point)로 세요(`EntryController.java:137`). 화면의 `maxLength`와 `message.length`는 UTF-16 단위로 세요.
   - 그래서 이모지는 화면에서 2자로 세어져요. 예를 들어 이모지가 많은 칭찬은 500자보다 훨씬 짧아도 입력이 막히고, 글자 수 표시도 실제보다 크게 나와요.
   - `maxLength`는 앞뒤 공백을 지우기 전 길이에 적용돼요. PRD는 "공백을 지운 뒤 1~500자"예요.

3. **받는 사람(to)에 PRD에 없는 규칙이 붙어 있어요** (`EntryController.java:73,144-157`)
   - PRD에는 "비어 있거나 없어도 저장돼요"라는 말만 있어요.
   - 서버는 41자 이상이면 400으로 거절하고, 문자열이 아닌 값(숫자 등)도 400으로 거절해요.
   - 동작이 틀렸다기보다 PRD에 적혀 있지 않은 규칙이에요. PRD에 적을지, 규칙을 뺄지 정해야 해요.

## PRD와 직접 어긋나지는 않지만 확인할 만한 곳

4. **처음 목록을 불러오는 중에 글을 저장하면 새 글이 화면에서 사라질 수 있어요** (`App.jsx:52` vs `89`)
   - 늦게 도착한 GET 결과가 목록 전체를 덮어써서, 방금 저장한 글이 보이지 않을 수 있어요.
   - DB에는 저장돼 있어서 새로고침하면 다시 보여요.

5. **목록을 못 불러온 뒤 글을 저장하면 오류 문장과 카드가 함께 보여요** (`App.jsx:152-158`)
   - 오류 문장이 그대로 남은 채 새 카드가 나타나요.

6. **DB 위치가 서버를 켠 폴더에 따라 달라져요** (`application.properties:6`)
   - DB 주소가 상대 경로(`data/praise.db`)예요.
   - 지금 `launch.json`처럼 `api/` 폴더에서 켜면 괜찮아요. 다른 폴더에서 켜면 새 DB가 만들어져서, 재시작 뒤 "글이 남는지" 확인할 때 글이 없는 것처럼 보일 수 있어요.

## PRD대로 되어 있는 것
- API 응답 모양
- 최신 글부터 200개
- 앞뒤 공백 제거와 길이 검사
- 400/413/415/404 오류와 `{"error": ...}` 모양
- UTC ISO 형식의 `created_at`
- 저장하는 동안 버튼 막기
- 서버 오류를 문장으로 보여 주기
- 사용자가 쓴 글을 글자 그대로 보여 주기(JSX라서 HTML로 넣지 않음)
- 로그인·수정·삭제·페이지 나누기·검색 없음

PRD에 따로 적히지 않은 405 응답도 같은 `{"error": ...}` 모양으로 답해요.
